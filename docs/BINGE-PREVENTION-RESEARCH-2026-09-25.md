# 過食アラート v2 研究設計 — 「頻度を上げて精度を落とさない」は可能か（2026-09-25）

熊田さんの依頼:
> 過食アラートの機能をアップデートして。具体的には頻度を多くする。ただし精度は落とさない。これを両立することは論理的に可能かを徹底的に検証して。どんな付加的なデータを過食と紐づけて検証するべきか、現在より客観的なリスク分析に基づいて精細にアラートを出すことは可能か。
> 研究だと思って徹底的に過食を防ぐ仕組み（追加のデータの取得をアプリの設計に組み込んでも良い）を考えつくして。

この文書は**研究設計書**として書く。結論 → 数式 → データ → モデル → 評価 → 取得すべきデータ → 介入 → オーナーの判断事項、の順。
実装コアは `native/src/lib/bingeRisk.ts`（純関数・jest 25件 `native/src/lib/__tests__/bingeRisk.test.ts`）。数式は平文記法（Φ=標準正規分布の累積分布、σ(z)=1/(1+e^−z)、log は自然対数）。

---

## 0. 要旨（5行）

1. **同じ判別力のままでは、頻度を上げれば精度は必ず下がる。** これは Neyman–Pearson の補題から従う数学的事実で、設定や工夫では回避できない（§2）。
2. **両立できる道は3つだけ**: ①判別力（AUC）そのものを上げる＝過食と結びつく情報を増やす、②アラートを「段」に分けて段ごとに違う精度床を持つ（頻繁で軽い nudge／稀で重い warning）、③単位を「日」から「状況（夕方・空腹・予定）」に変えて、当たりやすい瞬間だけ鳴らす（§2.4）。
3. 現行の判定（`assessBingeRisk` の固定点数＋`evaluateAlerts` の法則駆動）は**精度が一度も測られておらず**、ラベルの定義も3つ併存している（+400 / +800 / 単食2,500）。まず**定義を1つに決め、本人の履歴でバックテストして現在地の精度を知る**ことが先（§1・§5）。
4. 提案モデルは「文献由来の集団事前分布 ＋ 本人の履歴」を **MAP ロジスティック回帰**で合成する透明な確率モデル。データが少ないうちは事前に張り付き、たまるほど本人の値へ動く。理由（どの条件が何倍寄与したか）を毎回言葉で出せる（§4）。**精度が落ちたら自動で頻度を絞る自己制限ガード**を持つので、「精度を落とさない」は運用上も機械的に保証される（§5.4）。
5. 情報を増やす候補は、**期待情報量／取得負担**の比で並べると「夜の渇望チェック（1タップ）」「満腹超えタグ」「朝のストレス1問」「HealthKit の安静時心拍・HRV・手首温」「飲酒フラグ」の順。まずは追加入力なしで到達できる AUC を測り、その上で1タップ入力を1つずつ足して情報量が増えたかを同じ物差しで確かめる（§3・§6）。

## 1. 問題の定式化

### 1.1 いまアプリの中で「過食」は3通りに定義されている

| 場所 | 定義 | 使われ方 |
|---|---|---|
| `lib/insights.ts isBingeDay` | 超過 diff ≥ **+400** kcal **または** 気分・メモに「爆食／食べすぎ／過食…」の語（`detectStruggle`） | 事前検知 `assessBingeRisk`（曜日癖 R4）、引き金レポート `bingeAnalysis`、法則 `binge_trigger`／`recover` |
| `lib/features.ts DayFeature.binge` | 超過 over ≥ **+800** kcal **または** 摂取 > **2,500** kcal（自己申告は見ない） | 相関エンジン `correlate.mineRules('binge')`、気づきアラート、法則 `sleep_debt_binge`／`mood_lag_binge`／`multi_binge` |
| `log.tsx` G2 | **1回の食事**が 2,500 kcal 超 | 保存直後の非審判表示 |

同じ「食べすぎ」という言葉で、基礎率（1日あたりの発生確率 π）が2倍以上違う事象を扱っている。+400 なら π はおそらく 15–25%／日（減量中の目安からの超過は珍しくない）、+800 なら 5–10%／日。**§2 で示すとおり、精度の上限は π で決まる**ので、定義を決めないと「精度」を語れない。

### 1.2 提案する操作的定義（ラベリング手順）

過食 y_t ∈ {0,1} を**日 t** について次のように定める（実装: `bingeRisk.labelOf`。現状は `DayFeature.binge` をそのまま使い、閾値はオーナー決定後に定数1か所で変える）:

- **主ラベル（客観）**: `over_t ≥ B` または `intake_t > 2,500`。B の候補は 800（現行 features）／**600（推奨）**／400（現行 insights）。
  - 推奨 600 の理由: +400 は「外食1回」で普通に超えるため**行動としての過食**（制御喪失を伴う摂取）と区別がつかず、+800 は基礎率が低すぎて §2 の表のとおり週1本を超えるアラートが理論的に成立しない。中間の 600 で π ≈ 10%／日を狙い、後述の自己申告で補正する。
- **副ラベル（主観・任意）**: 食事に「満腹を超えて食べた」タグ（§6-2）または夜の渇望チェックで「抑えられなかった」。**主観ラベルが付いた日は over の値に関係なく y=1**。逆に主観で「これは計画したごほうび」（§6-5）が付いた日は、over が大きくても **y=0**（計画的な超過は防ぐ対象ではない）。
- **不明**: `intake_t` が null の日（未記録）は y_t = 不明 → 学習にも評価にも使わない。「未記録＝過食」と決めつけない（QA の「責めない」ゲート）。ただし**前日の未記録**は特徴量として使う（過食の翌日に記録が途切れる観察がすでにある）。

主観ラベルの根拠: 過食の臨床定義（DSM-5 の binge eating）は「客観的に大量」**かつ**「制御喪失感」の2要件。kcal だけでは後者が取れない。ただし診断はしない（`docs/STRATEGY.md` §5・`cycle.ts` と同じ線）。ラベルは本人の言葉の翻訳であって判定ではない。

### 1.3 予測ホライズン（いつ、何を予測するか）

| 時点 | 予測対象 | 使える情報 | 実装 |
|---|---|---|---|
| **朝**（起床〜+5h の窓・`wakeTime.ts`） | 今日1日のどこかで y_t=1 | 前日までの記録・昨夜の睡眠・曜日・周期・今日の予定（dayPlan） | `assessBingeRiskV2(rows, today, ctx)` の `pDay` |
| **夕方〜夜**（17時以降） | 今夜 y_t=1 | 上に加えて、いまの時刻・最後の食事からの経過・今日ここまでの摂取／たんぱく質 | 同 `pNow`（`intradayLogit` で時間内ハザードを加算） |

朝と夜で**同じモデルの確率を時間で条件付け**する（別モデルにしない）。理由: ラベルは日単位でしか取れないので夜だけのモデルは学習できない。時間内ハザードは文献由来の事前分布のみ（§4.3）で、将来「渇望チェック」が入れば夜の直接ラベルで学習に切り替える。

### 1.4 決定規則

確率 p を段（tier）に写す:

- `quiet`（何も出さない）／`nudge`（食事タブの控えめなカード。コスト小）／`warning`（朝の通知＋目立つカード。コスト大）
- 閾値は**期待効用**から出す（§4.4）: 出すべきなのは p × (防げる利益) × (介入の効きめ) > (誤報のコスト) のとき。
- さらに**本人の基礎率による床**: nudge は p ≥ 1.5 π̂、warning は p ≥ 3 π̂ でなければ出さない（π̂＝本人の過食率）。「平均より低い日に警告する」ことを防ぐ。
- 週予算（nudge 4本／warning 2本）と自己制限ガード（§5.4）が上限を守る。

## 2. 「頻度を上げて精度を落とさない」は論理的に可能か

### 2.1 記法と恒等式

- π = P(y=1)：基礎率（1日あたりの過食確率）
- α = P(アラート)：1日あたりのアラート率。週あたり本数 = 7α
- TPR = P(アラート | y=1)：再現率（recall）、FPR = P(アラート | y=0)
- 恒等式: **α = π·TPR + (1−π)·FPR**、 **精度 = P(y=1 | アラート) = π·TPR / α**

したがって 精度 × α = π × TPR。**精度を保ったまま α を2倍にするには TPR も2倍**でなければならない。TPR ≤ 1 なので、精度を保った頻度の上限は α_max = π / 精度（例: π=0.08・精度0.5 なら α ≤ 0.16／日＝週1.1本が**どんなモデルでも越えられない天井**）。

### 2.2 固定の判別力では精度は α の単調減少関数（Neyman–Pearson）

スコア s（何であれ「危険度」）に対して、閾値 c でアラートを出す規則 {s ≥ c} を考える。Neyman–Pearson の補題により、与えられた α に対して TPR を最大にする規則は尤度比 L(s) = p(s|y=1)/p(s|y=0) の閾値規則であり、L が s について単調なら閾値規則と一致する。閾値 c を下げて α を増やすと、新たに加わる日の集合 {c' ≤ s < c} の過食率は P(y=1 | c' ≤ s < c) ≤ P(y=1 | s ≥ c)（尤度比が単調減少）なので、混ぜた後の精度は必ず下がる。

**結論**: 同じスコア（同じ情報）で α を上げれば、精度は下がる。これは「閾値を工夫する」問題ではなく、情報の問題。

### 2.3 数値化（二正規 ROC モデル）

スコアが 過食日〜N(d′,1)、非過食日〜N(0,1) に従うとする（AUC = Φ(d′/√2)）。閾値 c で α(c) = π(1−Φ(c−d′)) + (1−π)(1−Φ(c))、精度 = π(1−Φ(c−d′))/α。実装 `bingeRisk.binormalPrecision` で計算した値（π = 0.08／日）:

**同じ AUC で本数を増やしたときの精度（再現率）**

| AUC | 0.5本/週 | 1本/週 | 2本/週 | 3本/週 | 4本/週 |
|---|---|---|---|---|---|
| 0.65 | 18%（16%） | 16%（28%） | 13%（47%） | 12%（63%） | 11%（75%） |
| 0.75 | 29%（26%） | 23%（41%） | 17%（62%） | 14%（76%） | 12%（86%） |
| 0.85 | 45%（40%） | 33%（58%） | 22%（78%） | 16%（88%） | 13%（94%） |

**精度床を守ったまま出せる週あたり本数の上限**

| AUC | 精度≥0.2 | ≥0.3 | ≥0.4 | ≥0.5 |
|---|---|---|---|---|
| 0.60 | 0.02 | 0 | 0 | 0 |
| 0.65 | 0.31 | 0.02 | 0 | 0 |
| 0.70 | 0.87 | 0.16 | 0.03 | 0 |
| 0.75 | 1.44 | 0.45 | 0.15 | 0.05 |
| 0.80 | 1.91 | 0.82 | 0.37 | 0.17 |
| 0.85 | 2.28 | 1.17 | 0.66 | 0.37 |
| 0.90 | 2.54 | 1.48 | 0.95 | 0.63 |

読み方: 基礎率 8% では、**AUC 0.85 という（行動予測としては非常に高い）判別力でも、精度 50% を守れるのは週 0.4 本**。精度 30% なら週 1.2 本。「毎日出す」と「半分は当たる」は、日単位では両立しない。

同じ表を π = 0.15（定義を +500 に緩めた場合）で引くと、AUC 0.75 で 1本/週 39%・2本/週 31%、AUC 0.85 で 1本/週 54%・2本/週 39%。**定義（基礎率）の選び方が精度の天井を直接動かす**。

### 2.4 両立の条件（達成可能なのはこの3つの組み合わせだけ）

1. **情報を増やす（AUC を上げる）**。表の行を下に移動する唯一の方法。例: いまが「週1本・精度25%」なら二正規モデル上 AUC ≈ 0.77。これを**週2本・精度25%のまま**にするには AUC ≈ 0.92 が要る（AUC 0.90 で 2本/週 24%）。0.77 → 0.92 は、渇望チェックのような**直接の前駆症状**を取らない限り、既存の記録データの組み合わせだけでは届かない可能性が高い（§3）。
2. **段（tier）を分ける**。「精度」を1つの数字で語るのをやめ、段ごとに違う床を持つ。AUC 0.80・π 0.08 の例: 上位 0.5本/週を warning（精度 36%・再現率 32%）、次の 2.5本/週を nudge（限界精度 11%）。合計 3本/週・全体の再現率 82%。**nudge の「誤報」のコストを、無視できるほど小さく設計できるか**（§7）が段分けの成立条件。
3. **単位を変える**。「日」ではなく「状況」（夕方17時以降・最後の食事から5h以上・予定あり）に対して鳴らす。状況の基礎率は日より高い（過食の大半は夕方〜夜に起きる: Smyth 2009）。§4.3 の時間内ハザードがこれ。ただし状況ラベルが無い現状では事前分布のみで、精度は測れない → §6-1 の渇望チェックが状況ラベルになる。

「頻度を上げたい」の裏にある本当の要望は「**危ない日を見逃したくない**」（再現率）だと解釈する。段分け＋自己制限ガードなら、再現率を上げつつ「重い警告の精度」を守れる。**両立は、精度を『段ごとに』定義し直すことで可能**、が答え。

### 2.5 例題（数値で追う）

本人 A: 記録 90 日、+600 超過が 9 日（π̂ = 0.10）。モデルのバックテストで AUC 0.78。

- warning 閾値 0.39（§4.4）→ 該当 4 日、うち過食 2 日: 精度 50%・再現率 22%・0.31本/週
- nudge 閾値 max(0.156, 1.5×0.10=0.15) = 0.156 → 該当 20 日、うち過食 6 日: 精度 30%・再現率 67%・1.6本/週
- 何も出さない残り 66 日に過食 1 日（見逃し 11%）

「1.6本/週で3割当たる／0.3本/週で半分当たる」が本人 A の現在地。ここに「夜の渇望チェック」を足して AUC が 0.85 に上がれば、同じ閾値で nudge の精度は 30% → 約 40% に、warning の本数は 0.3 → 0.6本/週に増える（表の 0.85 行）。**「頻度を上げる」は、こうして測った上で初めて意味を持つ**。

### 2.6 現行判定の評価

- `assessBingeRisk`（`insights.ts`）: 5 ルールの整数点数（連続赤字 +2、大赤字 +1、たんぱく質 +1、曜日 +2、つらいサイン +2）。点数の重みは文献でも本人データでも較正されていない。R4 の曜日は「過食の半分以上が同じ曜日」という条件で、過食が 3 回しかない人では 2 回同じ曜日なら成立（偶然で 2/7≈29%…3回中2回が一致する確率は約 1−(6/7)(5/7)≈39%）。**偽陽性の温床**。
- `evaluateAlerts`（`correlate.ts`）: 採択ルール（リスク比 ≥1.5・支持度 ≥6）の条件側を今日が満たしたら発火。ルールの採択は**多重比較の制御が無い**（§3.2）ため、90 日で 19 条件の 2〜3 因子組を探索すると偶然のルールが混ざる。さらに「ルールが成立＝その条件の日は過食率が高い」であって、**その日の確率がいくつか**（閾値を超えるか）は見ていない。
- 抑制（同 id 1日1回・3日連続で休む）は慣れ防止としては良いが、精度の観測が無いので「当たらないアラートが出続ける」状態を検出できない。
- **測定が無い**: 出したアラートがその日当たったかを記録していない（`bl-insight-alert-history` は id と日付のみ）。精度を「落とさない」には、まず**精度を測る**必要がある（§5.4 の `AlertOutcome` 履歴）。

## 3. 過食と紐づけて検証すべき追加データ（ランキング）

並べ方: **期待情報量**（文献の効果量 × 本アプリでの発生頻度）÷ **取得コスト**（実装＋本人の負担）。★は 3 段階。「出どころ」は本アプリでの取得手段。

| 順 | 因子 | 仮説の向き | 文献（効果量） | 出どころ | 情報量 | コスト |
|---|---|---|---|---|---|---|
| 1 | **夜の渇望・制御感**（0–3、17–21時に1タップ） | 高いほど今夜の過食↑（最も近接した前駆） | EMA メタ解析: 過食前に負の感情が上がる d=0.63（Haedt-Matt & Keel 2011）。OnTrack は EMA 回答でラプスを予測し体重減 3.1%（Forman 2019） | **新規 1 タップ**（§6-1） | ★★★ | ★（1日1回・不確実な日だけ） |
| 2 | **前日の制限**（赤字 ≥300・3日連続赤字） | 制限した当日と翌日に過食のオッズ↑ | Zunker 2011（BN・EMA）: 当日と翌日に有意、2日前は追加情報なし | 収集済み `over` | ★★★ | 0 |
| 3 | **前日の過食（連鎖）**・直近 7 日の過食 | 翌日も過食しやすい | Zunker 2011。本アプリ `bingeAnalysis.after.chainRate` | 収集済み `binge` | ★★★ | 0 |
| 4 | **睡眠**（昨夜 <6h・5日負債 ≥5h） | 摂取↑（平均 +385 kcal） | Al Khatib 2017 メタ解析（17研究 n=496） | HealthKit 収集済み `sleep_h`／`sleep_debt5` | ★★ | 0（連携者のみ） |
| 5 | **気分**（前日 ≤2／3日平均 ≤2.5） | 低いほど↑ | Haedt-Matt & Keel 2011、Goldschmidt 2014（ストレス→負の感情→過食） | 収集済み `mood`（朝のカード） | ★★ | 0 |

| 11 | **黄体期**（周期 15 日目以降） | 中黄体期にピーク | Klump 2013（エストラジオール×プロゲステロン） | 収集済み `cycle_day`（周期モード ON のみ） | ★★（該当者） | 0 |

| 13 | **安静時心拍・HRV（SDNN）・呼吸数・手首温** | ストレス／睡眠の質の生理指標。低 HRV・高 RHR で↑ | 摂食障害での HRV 異常は再現性が不安定（Watford 2020 メタ解析、BED 単独では有意差なし） | **HealthKit 追加許可**（§6-6・要オーナー判断） | ★（個人内変化として） | ★★（許可ダイアログ・プライバシーラベル） |
| 14 | 前日の運動負荷（アクティブ ≥500・トレ） | 代償性の食欲↑（個人差大） | 本アプリ `bingeAnalysis 'hard-exercise'` | 収集済み | ★ | 0 |
| 15 | 体重の反発（7日 +0.5kg） | 落胆→「どうせなら」 | 逆制御理論（Polivy & Herman） | 収集済み `weight_delta7` | ★ | 0 |
| 16 | 記録の途切れ（前日未記録） | 過食の前後で記録が途切れる | 本アプリの観察 `logDropRate` | 収集済み | ★ | 0 |

**優先順の含意**: 順位 2〜5・7〜8・10〜11 は**追加入力ゼロ**で、すでに `DayFeature` から派生できる（実装済み `RISK_FEATURES` 16 種）。まずこれだけで AUC を測る（§5）。順位 1 の渇望チェックは唯一「情報量★★★ で新規」＝**AUC を 0.85 超に持ち上げる可能性がある唯一の候補**。HealthKit の生理指標は文献上の再現性が低く、集団レベルの事前重みが置けないので、**個人内の逸脱（本人の 28 日中央値からの z スコア）**としてだけ使い、事前重み 0・本人データのみで学習させる位置づけが妥当。

### 3.1 現行 `laws.ts`／`correlate.ts` の統計的健全性の評価

良い点:
- リスク比の分母 0 に Haldane 補正（0.5）を入れ、5 倍で頭打ち → 「∞倍」を出さない。
- 最小支持度 6・両群 4 日以上・n ≥ 14 の安全弁。アプリオリの単調性で探索を絞る。
- 部分集合よりリスク比が上がる組だけ採択（説明に要らない因子を足さない）。
- 文言が「〜のとき〜が起きやすい」で因果を言わない。

弱い点（v2 で直すべきもの）:
1. **多重比較が制御されていない**。19 の朝条件から 1〜3 因子の AND を探索すると候補は数百。リスク比 ≥1.5 という閾値だけでは、n=30〜90 日の系列で偶然の組が採択される。`binge_trigger`「引き金 1 位」は最大値を取るので**勝者の呪い**（上振れした推定値が選ばれる）を必ず含む。
2. **リスク比の不確実性を見ていない**。該当 6 日中 2 回（33%）vs 非該当 40 日中 4 回（10%）でリスク比 3.3 だが、95% 信頼区間は概ね 0.7〜15。信頼度 `confidenceOf` は n だけで決まり、比の分散を使っていない。
3. **リスク比は確率ではない**。「2 倍」は基礎率 5% なら 10%、30% なら 60%。アラートの是非は絶対確率で決めるべき（§4.4）。
4. **ルールの AND は相関する因子を二重に数えない代わりに、OR の情報を捨てる**。回帰モデルなら「睡眠不足 0.4 ＋ 気分低下 0.6」のように加算し、相関があれば係数が自動で調整される。

### 3.2 端末内での検証手順（因子ごとの妥当性検定）

各因子 j について、朝の時点で分かる 2 値 x_j と結果 y の 2×2 表 (a,b,c,d) = (x=1&y=1, x=1&y=0, x=0&y=1, x=0&y=0) を作り:

- **条件付き確率（ラプラス平滑化）**: P̂(y=1|x=1) = (a+1)/(a+b+2)、P̂(y=1|x=0) = (c+1)/(c+d+2)。0 件でも 0% と言わない。
- **効果量**: log オッズ比 = log((a+0.5)(d+0.5)/((b+0.5)(c+0.5)))、標準誤差 SE = √(1/(a+.5)+1/(b+.5)+1/(c+.5)+1/(d+.5))。
- **最小支持度**: a+b ≥ 6 かつ c+d ≥ 6（現行と同じ）。
- **多重比較**: 因子ごとの p 値（Wald: z = logOR/SE）を **Benjamini–Hochberg（FDR 10%）**で補正して「法則」として口に出す因子を選ぶ。探索した候補数 m を分母にする（多要素ルールなら探索した組の数）。Bonferroni は保守的すぎて 90 日では何も残らないので BH を採る。
- **勝者の呪いの緩和**: 「引き金 1 位」の倍率は表示前に**縮小**する（§4 の MAP 推定がまさにこれ。事前 0.5 と観測 1.2 を分散で加重平均すると 0.8 程度に落ち着く）。
- **法則の表示とアラートの発火は分ける**: 法則は「発見の物語」（BH で厳しめ）、アラートは「確率が閾値を超えたか」（縮小済み係数の合計）。前者を後者の条件にしない。

## 4. 提案モデル（個人・端末内・透明）

### 4.1 構造

日 t の朝に分かる 2 値特徴 x_t = (x_1, …, x_K)（K=16・§4.2）に対して

  **logit P(y_t=1 | x_t) = w_0 + Σ_j w_j x_j**

係数 w = (w_0, …, w_K) を **MAP 推定**（ガウス事前分布つき最尤）で求める:

  最小化 L(w) = Σ_t [ log(1+e^{z_t}) − y_t z_t ] + ½ Σ_j (w_j − m_j)² / τ_j² 、 z_t = w·x_t

- m_j = 集団の事前重み（文献由来・§4.2）、τ_j = 事前の標準偏差（既定 0.7＝±2τ で ±1.4 log-odds ≒ 4 倍まで本人データで動ける）。切片は m_0 = logit(0.08)、τ_0 = 1.5（基礎率は本人差が大きいので速く動かす）。
- **縮小の意味**: 観測が 0 件なら w = m（事前どおり）。観測が増えるほど尤度項が支配し、w は本人の値へ。1 因子で見れば w_j ≈ (m_j/τ_j² + ŵ_j/SE_j²) / (1/τ_j² + 1/SE_j²) の精度加重平均＝経験ベイズ縮小そのもの。
- **解法**: Newton 法（勾配 g = Xᵀ(σ(z)−y) + Λ(w−m)、ヘッセ H = XᵀSX + Λ、S=diag(σ(1−σ))）。Λ が正なので H は常に正定値＝**完全分離（ある条件の日が全部過食）でも発散しない**。決定的（乱数なし・初期値=事前平均・バックトラッキング付き）。16 特徴×90 日なら 10 反復以下・数 ms。
- **欠測**: x_j = null（判定不能）は 0 として扱う＝「証拠なし」。睡眠連携が無い人は睡眠の項が常に 0 で、他の項だけで判定される。
- **説明**: 各項 w_j x_j が「理由」。正の寄与を大きい順に最大 4 件（`topReasons`）。「昨夜の睡眠が6時間未満（+0.5）」のように**何がどれだけ**を出せる。

| deficit_streak3 | 前 3 日すべて over < 0 | +0.4 | 逆制御理論・本アプリ R1 |
| prev_binge | 前日 binge | +0.6 | Zunker 2011・chainRate |

事前重みの桁は「文献のオッズ比 1.3〜2.0 → log で 0.25〜0.7」に対応させ、再現性の弱いものは小さく置いた。**事前は出発点であって結論ではない**（本人データで上書きされる）。将来 §6 の新規入力が入ったら行を足すだけ（列を増やしても学習は同じ）。

### 4.3 時間内ハザード（同じ日の中での危険の集中）

  logit P(今夜) = logit P(今日) + h(時刻, 空腹時間)、 h = min(1.0, [17時〜 +0.3 / 20時〜 +0.6] + [5h〜 +0.3 / 7h〜 +0.5])

- 事前分布のみ（日ラベルでは学習できない）。過食の大半が午後遅く〜夜に集中する（Smyth 2009）・長い食事間隔で次の食事量が増える、という 2 つの一般知見を、控えめな上限 +1.0（≒2.7 倍）で織り込む。
- 夕方の判定に使うのは「いま鳴らすべきか」だけ。**朝の判定と二重には出さない**（朝に nudge が出ていれば夕方は同じカードの文言を更新するだけ）。
- §6-1 の渇望チェックが入れば、h は本人データで学習できる（渇望 ≥2 の夜の過食率で係数を較正）。

### 4.4 段の閾値（期待効用）と基礎率床

アラートを出す条件: p × B × e > C（B=過食 1 回を防ぐ利益、e=介入の効きめ、C=誤報のコスト）⇔ **p > C/(B·e)**。相対値で置く:

| 段 | C | B | e | 閾値 p* |
|---|---|---|---|---|
| nudge（控えめなカード） | 1 | 8 | 0.8 | **0.156** |
| warning（通知＋目立つカード） | 2.5 | 8 | 0.8 | **0.39** |

B=8 は「過食 1 回（+800 kcal ≒ 脂肪 0.1 kg 相当＋翌日の連鎖・記録離脱リスク）を防ぐ価値は、控えめなカード 8 枚ぶんの注意コストに等しい」という判断。e=0.8 は OnTrack の RCT（Forman 2019）で計画外ラプスが減った観察から、介入が届いた場合の効果を高めに置いた。**この 3 つは製品判断なので定数 1 か所（`NUDGE_UTILITY` / `WARNING_UTILITY`）に置き、オーナーが動かせる**。

基礎率床（`LIFT_FLOOR`）: nudge は p ≥ 1.5 π̂、warning は p ≥ 3 π̂。π̂ が 0.3 の人（週 2 回過食）では nudge 0.45・warning 0.9 に上がる＝毎日鳴らない。

### 4.5 現行より優れる点

1. **絶対確率**を出す（リスク比や点数ではない）→ 閾値を効用で決められ、較正を測れる。
2. **少データで暴れない**（事前分布への縮小）→ 記録 14 日から静かに使える。
3. **相関する因子の二重計上を回帰が調整**（睡眠不足と気分低下が同じ日に多い人で、両方を足して過大評価しない）。
4. **理由が数値つきで出る**（w_j x_j）→ 法則図鑑の解説記事と同じ文法で説明できる。
5. **未来を見ない検証**（§5）と**自己制限**（§5.4）が仕組みとして入っている。

### 4.6 失敗モード（正直に）

- **ラベルの質**: 摂取の記録が過小申告なら y が付かず、モデルは「記録が丁寧な人の過食」だけを学ぶ。副ラベル（§1.2）で補う。
- **基礎率が低すぎる人**（90 日で過食 1〜2 回）: warning は永久に出ない。nudge の事前分布が支配し、実質「一般論のアラート」になる。readiness `prior` で nudge 止まりにしてあるのはこのため。
- **非定常性**: 減量期→維持期で基礎率が変わる。90 日窓のローリング学習で追随するが、切替直後 2〜3 週は遅れる。
- **共変量シフト**: 「予定あり」の日は dayPlan が配分を緩めるので over が出にくい → planned_event の係数が本人データで下がる。これは正しい挙動（介入が効いている）だが、係数を「予定は危なくない」と誤読しないこと。
- **介入の効果でラベルが消える**: 当たったアラートは過食を防ぐので「外れ」に見える（精度の過小評価）。§5.4 の精度床はこれを織り込んで低めに置く。正確に測るには A/B（アラートを出さない日をランダムに混ぜる micro-randomized trial）が要るが、**本人の不利益になる実験はしない**。代わりに「アラートを閉じた（読んだ）日」と「読まなかった日」の過食率差を観察指標にする。

## 5. 評価プロトコル

### 5.1 ローリング・オリジン検証（`backtestBingeRisk`）

日 t の予測は **t より前の日だけ**で学習したモデルで出す（未来を見ない）。結果が分かる日だけ評価。学習日数 < 14 の t は飛ばす。出力: 予測列 {(date, p, y)}、Brier、基礎率 Brier、AUC、較正ビン、段ごとの精度・再現率・週本数。

### 5.2 指標

- **precision@k 本/週**（`alertsAtPrecision` の逆関数）: 確率上位 k 件の過食率。運用の「頻度」の言葉に直結。
- **再現率**: 過食日のうちアラートが出ていた割合（見逃し率の補数）。
- **Brier** = 平均 (p − y)²。「常に基礎率」の Brier（climatology）を**下回らなければ情報がない**。合成データの検証では、情報のある世界で 0.094 vs 0.110、無い世界で 0.102 vs 0.102（差なし）。
- **較正ビン**（0–5%／5–10%／10–20%／20–35%／35–50%／50%–）: 各ビンの平均予測 vs 実際の発生率。ずれが 1.5 倍を超えるビンがあれば閾値を動かす前に較正（Platt/温度スケーリング）。
- **AUC**（Mann–Whitney）: 判別力の要約。§2 の表と突き合わせて「この AUC で出せる本数」を読む。

### 5.3 最低データ量（`readinessOf`）

| 状態 | 条件 | 出せる段 |
|---|---|---|
| silent | 結果が分かる日 < 14 | 何も出さない |
| prior | 14〜27 日、または過食 < 3 回 | nudge のみ（事前分布が支配） |
| full | ≥ 28 日かつ過食 ≥ 3 回 | warning も可 |

現行カードは 5 日で出るが、5 日では「あなたの」と言えない。14 日は相関エンジンと同じ線（`correlate.MIN_DAYS`）。

### 5.4 自己制限ガード（`guardThresholds`・`withinWeeklyBudget`）

「精度を落とさない」を仕組みにする:
1. 出したアラートごとに `{date, tier, p, outcome}` を保存し、翌日以降に outcome（その日 y）を埋める（**現行には無い測定**）。
2. 直近 28 日の**結果が分かった**アラートについて段ごとの精度を計算。結果が分かったものが 6 件未満なら判断しない。
3. 精度が床（nudge 0.15＝基礎率 8% の約 2 倍／warning 0.30）を下回ったら、閾値を (床／観測精度) 倍（上限 2 倍）に上げる → 頻度が自動で減る。
4. 閾値は**基準（期待効用の線）より下には決して動かない**。精度が戻る、または古い失敗が 28 日の時効で消えれば基準に戻る（自己回復）。
5. 週予算: nudge 4 本／warning 2 本（直近 7 日）。

この 5 点で「頻度を上げたら精度が落ちた」という状態は**最長 28 日で自動修正**される。

### 5.5 合成データでの実証（jest・決定的）

- 情報のある世界（真の係数あり・周辺過食率 12.6%・300 日）: AUC 0.80、Brier 0.094 < 0.110、精度床 0.35 を守れる本数 **1.3 本/週**、warning 11 件中 6 件的中（55%）、nudge 55 件中 19 件（35%）。
- 情報の無い世界（係数ゼロ・同じ過食率）: AUC ≈ 0.5、Brier は基礎率と同じ、精度床 0.35 を守れる本数 **0 本**。
- 同じモデルで上位 5 件 ≥ 上位 25 件 ≥ 上位 60 件の精度（単調）。
- 14 日の学習では係数の事前からの逸脱は平均 0.09（最大 0.47 < τ）、400 日では真値へ移動（事前 0.5・真値 2.0 の因子が 1.2 超へ、事前 0.6・真値 0 の因子が 0 側へ）。
- ガード: 10 件中 1 件的中（10% < 15%）で nudge 閾値が上がり、5 件的中では基準のまま。未解決・28 日超・6 件未満は数えない。

## 7. 介入設計（アラートが何を起こすか）

ゲート（`docs/STRATEGY.md`）: 責めない・診断しない・1 日の崩れで人を崩さない。**アラートは予報であって採点ではない**。文言は「今日は〜が起きやすい条件」「もしよければ」で統一し、「我慢」「太る」「失敗」は禁止語（`whatIf.ts` と同じ総当たり検査を文言に掛ける）。

| 段 | いつ | 出し方 | 用意する行動（1 タップ） | 根拠 |
|---|---|---|---|---|
| nudge（朝） | pDay ≥ 0.156 | 食事タブのカード 1 枚（既存 caution 枠・理由を最大 3 行） | ①「たんぱく質を朝昼に前倒し」（whatToEat を朝の文脈で開く） ②「今日は +200 kcal 緩める」（既存 recovery 枠） ③「夕方に一声かけて」（#1 の渇望チェックを予約） | 前倒しは満腹感（Leidy）、緩めは逆制御の予防（制限が引き金なら制限を弱める） |
| nudge（夕方） | pNow ≥ 0.156 かつ朝は quiet だった | 同じカードの文言更新（「夕方になって条件が重なりました」） | ①「10 分だけ待つ」タイマー（urge surfing・渇望は波で 15〜20 分で引く） ②「何を食べる？」で夕食を決めてしまう（決めた食事は暴走しにくい: 事前コミットメント） | 衝動の時間減衰・実装意図（if-then プラン） |
| warning | pNow ≥ 0.39・readiness full | 朝の通知（smart のときだけ・1 日 1 件・既存 `planMorningNotification`）＋カード | nudge の 3 つ＋「今夜のプランを 1 行で決める」（dayPlan に「夜: ◯◯を食べる」の自由記入・翌日に振り返り） | 事前コミットメントは高リスク日ほど効く |
| 事後（翌朝） | 前日 y=1 | 既存のおかえり文法（「昨日はこんな日。1 週間単位ではまだ問題ありません」） | 「今日の目標をならす」（carryover）・アラートの結果を静かに記録（ガードの outcome） | 連鎖（prev_binge +0.6）を切るのが翌日の最重要介入 |

**出さない**ことも介入: quiet の日は何も言わない。アラートの価値は希少性で決まる（§5.4 の週予算はこのため）。

## 8. 実装状況と配線指針（親エージェント向け）

実装済み（このブランチ・UI なし）:
- `native/src/lib/bingeRisk.ts`: `RISK_FEATURES`（16 特徴・事前重み）、`featureVector`／`labelOf`、`fitMapLogistic`（Newton・ガウス事前）、`fitRiskModel`／`predictRisk`／`assessBingeRiskV2`、`intradayLogit`、`thresholdFromUtility`／`effectiveThresholds`／`tierOf`、`guardThresholds`／`withinWeeklyBudget`、`backtestBingeRisk`＋`brierScore`／`aucOf`／`calibrationBins`／`precisionRecallAt`／`alertsAtPrecision`、理論値 `binormalPrecision`／`maxAlertRateAtPrecision`。
- `native/src/lib/__tests__/bingeRisk.test.ts`: 25 件（特徴／縮小／頻度と精度／較正／ガード／段）。

配線するときの注意:
1. `buildDayFeatures(90)` → `assessBingeRiskV2(rows, todayJST(), { plannedEvent: dayPlan?.kind, hour: jstHourNow(), hoursSinceLastMeal })`。`hoursSinceLastMeal` は今日の `logs.at` の最大値から。
2. 段が `quiet` でなければ既存 caution 枠に載せる（`logCards` の調停はそのまま・MORNING_ONLY もそのまま）。`reasons[].label` は日本語原文なので `t()` に通し、辞書に **16 キー**を足す（`correlate.conditionLabel` と同じくリテラル switch を置く）。
3. アラートを出した日は `AlertOutcome{date,tier,p,outcome:null}` を AsyncStorage（例 `bl-binge-alerts`・90 日で掃除）に積み、翌日以降 `buildDayFeatures` のたびに `outcome` を `labelOf` で埋める。`guardThresholds(history, DEFAULT_THRESHOLDS, today)` の結果を閾値に使う。
4. 現行 `assessBingeRisk`（insights.ts）と `evaluateAlerts` の caution は、v2 が `silent` の間だけ従来どおり出す（移行期間）。v2 が `prior` 以上になったら v2 を正とし、法則駆動の caution は「理由の一つ」として reasons に合流させる（同じ条件なら重複表示しない）。
5. 設定に「過食アラートの頻度: 控えめ／ふつう／多め」を置くなら、`NUDGE_UTILITY.costFalseAlarm` を 1.5／1／0.7 に写像する（閾値 0.23／0.156／0.11）。**warning の閾値は動かさない**（重い割り込みの精度は製品が守る）。
6. 過食の定義 B（§1.2）を決めたら `features.ts BINGE_OVER` を変え、`PRIOR_BASE_RATE` を 600 なら 0.10、400 なら 0.15 に合わせる。

## 9. オーナー（熊田さん）の判断事項

1. **過食の定義 B**: 800（現状）／**600（推奨）**／400。基礎率＝精度の天井を決める（§2.3 の 2 つ目の表）。
2. **主観ラベルを取るか**（#2 満腹超えタグ・#1 渇望チェック）。取るなら文言の規範（非審判）を先に決める。
3. **HealthKit の追加許可**（安静時心拍・HRV・呼吸数・手首温）。効果は個人内変化としてのみ・文献の再現性は弱い・プライバシーラベル申告が増える。**推奨: #1〜#4 の効果を測ってから**。
4. **効用の 3 定数**（誤報コスト 1／2.5・利益 8・効きめ 0.8）。nudge を「毎日出てもいい軽さ」にできるなら C を下げて頻度を上げてよい（その分 nudge の精度は下がる＝§2 の表どおり。それでも warning の精度は独立に守られる）。
5. **readiness の線**（14 日で沈黙・28 日＆3 回で全段）。現行の 5 日より遅い。早くしたいなら prior 段で nudge だけ、が安全側。
6. **移行**: 現行の点数式カードをいつ v2 に置き換えるか（§8-4）。
