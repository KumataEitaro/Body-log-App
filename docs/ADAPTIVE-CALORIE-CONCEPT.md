# 「自分にとっての最適なカロリー」解析（適応型 TDEE）構想メモ（2026-09-26）

熊田さんの構想: 摂取カロリーと消費カロリー、そしてその期間の体重変化を分析して、**自分にとっての維持カロリー（＝本当の消費カロリー）** を実測から解析する機能。

## 0. 結論（先に）
- **できる。しかも新しいデータは要らない。** 材料（日別の摂取 kcal・体重・目標 kcal・運動の取込・生理周期・目的の切替履歴）は全部 `entries` / `logs` / `purpose_periods` / `cycle_logs` に既にある。
- 原理はエネルギー収支の恒等式。**「摂取 − 体重変化ぶんのエネルギー ＝ 消費」** を 2〜4 週の窓で解く。MacroFactor が「Expenditure」として売りにしている計算と同じ系統（摂取と体重トレンドから決定論的に消費を推定し、2〜4 週で安定する）。
- BodyLog に固有の強み: **過食日・主観ラベル・アルコール・生理周期・目的（増量/減量）の切替**を持っているので、他社より「ノイズの出どころ」を説明できる。
- 出し方は **「維持カロリー ≈ 2,180 ±140 kcal」のように幅つき**で出し、**目標カロリーへの反映は手動ボタン**（自動更新はしない＝2026-09-24 の運動取込と同じ方針）。

## 1. 数式（純関数にする・`lib/adaptiveTdee.ts` 想定）
窓 W（例: 直近 21 日）について
```
Ī      = 窓の中で記録がある日の摂取 kcal の平均
slope  = 体重トレンドの傾き（kg/日）… ロバスト回帰（Theil–Sen）or EMA の差分
TDEĒ  = Ī − k × slope            k = 7,700 kcal/kg（脂肪換算。除脂肪の増減が混じると 5,000〜7,700 に振れる）
```
- **記録がある日だけ**を平均に入れる（未記録＝0 ではなく欠測）。1 日 < 0.6×BMR の日は「記録し忘れ」として除外候補。
- 体重は **1 点で信じない**。朝の実測の 1〜3 kg のぶれ（水分・グリコーゲン・内容物）を平滑化で消す。
- 不確かさ: 体重のばらつき σ_w（本人の実測から推定・だいたい 0.4〜0.8 kg）を傾きの標準誤差に伝播 → kcal の幅にする。記録日数 n と体重測定回数 m で幅が縮む。

### 事前分布と合成（ベイズ／カルマン風）
- 事前: 式の TDEE（Mifflin×活動係数＋運動取込）。幅 σ₀ ≈ 250 kcal。
- 観測: 上の実測 TDEĒ とその幅 σ₁。
- 事後 = 精度加重平均。**記録が少ないうちは式の値に寄り、貯まるほど実測に寄る**。自然に「最初は目安、だんだん本人の値」になる。
- 週 1 回（月曜の朝）に更新し、履歴を持つ（グラフ「あなたの消費カロリーの推移」）。

## 2. ノイズの扱い（ここが他社との差）
| 要因 | データ | 扱い |
|---|---|---|
| 月経周期の水分 | `cycle_logs`（設定 ON の人） | 開始 3 日前〜開始後 3 日の体重を窓から外す／重みを下げる |
| 過食日・アルコール | `logs.overfull` / `logs.alcohol`（migration-38） | 翌日の体重（水分）を外す。摂取は入れる（本当に食べた分） |
| 目的の切替（増量⇄減量） | `purpose_periods` | 切替日で窓をリセット（別の平衡状態） |
| 筋トレ開始・クレアチン | 筋トレ記録の急増 | 最初の 2 週は幅を広げる（グリコーゲンで +1 kg） |
| 記録の抜け | 未記録日 | 欠測扱い。窓に記録日 ≥ 10・体重 ≥ 4 点・期間 ≥ 10 日を要求。満たなければ「あと n 日記録すると出ます」 |
| 過少申告 | — | 補正しない。**「あなたの記録の物差しでの維持カロリー」**と明示する（これがこの機能の本質: 物差しごと較正する） |

## 3. 画面（案）
- **からだの分析ページの先頭カード「あなたの維持カロリー」**: 大きな数字 ± 幅、下に「記録 18 日・体重 9 回から推定」「式の目安 2,050 より +130」。折れ線で週ごとの推移。
- **目標との差**: 「いまの目標 1,700 は維持より −480/日 ≈ 週 −0.44 kg ペース」。目的（減量/増量）と体重目標・期限から **推奨目標**を出す。
- **「目標カロリーを更新する」ボタン**（手動）: 設定の目標シートへ値を渡す。自動では変えない。
- 食事タブのヒーロー「あと ◯ kcal」は目標が更新されたときだけ変わる（今の仕組みのまま）。
- 相談タブ: コーチのプロンプトに「実測の維持カロリー」を渡す（`lib/coachPrompt.ts`）。「なぜ減らないか」への答えが数字で言える。

## 4. 実装の見積もり
- `lib/adaptiveTdee.ts`（純関数: 窓の切り出し・ロバスト傾き・幅・事後合成）＋ jest（合成データ: 既知の TDEE と乱数の体重で回帰できるか／欠測・周期・切替の除外）… 0.5 日
- カード＋設定への受け渡し＋辞書 … 0.5 日
- 履歴の保存: 決定論的なので **保存不要**（過去の週も同じ関数で再計算できる）。表示が重ければ `bl-tdee-cache` に週ごとの結果をキャッシュ。
- DB 変更: なし。

## 5. 注意
- 医療的な断定はしない（「維持カロリー」は本人の記録に対する統計量）。
- 減量ペースが週 1% 体重を超える推奨は出さない（ガードは `lib/guard.ts` に集約）。
- 記録が薄い人には出さない（幅が ±400 を超えるなら「まだ目安」と表示）。
