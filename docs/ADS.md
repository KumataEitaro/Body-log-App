# 広告（AdMob）の実装と、公開までに必要な手順

2026-09-01（feat/ads）実装。無料プラン向け**アンカー型アダプティブバナー**。
2026-09-04（feat/ads-interstitial）で**インタースティシャル（全画面）を1箇所だけ**追加した
（概要タブのドリルダウン）。リワード・ネイティブ広告は使わない。

## いま何がどう動くか（コード側・対応済み）

- SDK: `react-native-google-mobile-ads`（Expo config plugin対応）
- 表示条件: `useGate()` が **active（=RCキー設定済みの課金有効ビルド）かつ plan が null/'free'**
  のときだけ表示。**現在の運用（RCキー未設定）では誰にも表示されない**。
  課金を解放するビルド（RCキー設定）と同時に広告も点灯する＝
  「ライト¥300の『広告なし』に実体がある」状態が仕組みで保証される（RELEASE-RISKS A1対策）
- 配置: **各タブに1枠**（2026-09-02 feat/ads-all-tabs で食事タブのみ→全タブへ拡張）。
  1画面に最大1枠。詳細ページ・法則記事・設定には置かない。枠一覧は下の節
- ATT: **初回リリースは非パーソナライズ広告（NPA）固定**。ATTダイアログは出さず、
  `requestNonPersonalizedAdsOnly: true` を全リクエストに付与、
  plugin側も `delayAppMeasurementInit: true`（安全側）。パーソナライズ化は将来の改善
- 広告の**上の行**に「広告を消す →」→ `/paywall?src=ads` の導線つき（2026-09-04 文言・位置を明記。
  広告ビューの外側。広告の上に × や閉じるボタンは絶対に置かない＝AdMob違反）
- 読み込み失敗・Expo Go・モジュール無し環境では高さ0（空白の枠を見せない）

## 枠一覧（タブ・位置・ユニット）

部品は3層: `components/AdSlot.tsx`（いつ出す・どう消える）→ `components/AdBannerView.tsx`
（ラベル＋導線＋BannerAd 本体・ユニットID）→ AdMob SDK。純関数は `lib/ads.ts`。

| placement | タブ | 位置（配置理由） | 使用ユニット |
|---|---|---|---|
| `log` | 食事 | **ヒーロー（「あと食べられる」＋残量）カードの直後**（2026-09-04 移設。以前は「今日の記録」直下＝スクロール2〜3画面目でほとんど見られていなかった）。司令塔行（解釈1行＋CTA）はヒーロー内なので広告はカードの**外**・直後に置き「数字→解釈→行動」の1画面を割らない。カード調停（logCards.ts）の対象カード群より**上**＝いちばん見られる位置で、調停対象が0枚の日でも位置が動かない。記録ボタン（右下＋・司令塔CTA）の直上には置かない | banner-ios / banner-android（共用） |

## 課金で「きれいに消える」仕組み

1. **表示可否**は `lib/ads.ts` の `shouldShowAd(active, plan)`＝active（RCキー設定ビルド）×
   plan が null/'free'。lite/standard/premium は出さない（既存ライト購入者にも出さない）
2. **状態遷移**は `nextAdSlotState`（hidden → loading → shown → collapsing → hidden）。
   - 見えている枠（shown）が対象外になった瞬間（課金完了）→ `collapsing`：Reanimated の
     `withTiming` で高さを実測値→0（`AD_COLLAPSE_MS`=180ms・`Easing.out(cubic)`）、下余白
     （12 / compact 8）も同じカーブで縮める。終わったら unmount。下のカードが跳ねない
   - 読み込み前（loading）に対象外になったら、高さを持っていないので即 hidden
   - 読み込み失敗は即 hidden（表示後の再読み込み失敗は畳んで消す）
   - 「視差効果を減らす」ON（`useReduceMotion`）はアニメ無しで即消す
3. **plan がいつ変わるか**（`lib/gate.ts`）。useGate は `useSyncExternalStore` の購読なので、
   キャッシュが変わった瞬間に全タブの AdSlot と王冠が同時に再判定される
   - **購入直後**: paywall `buy()` → `purchase()`（内部で `getCustomerInfo()` を再取得）→
     `applyEntitlement(newPlan)`：RC entitlement をその場で採用して通知、裏で `refreshGate()`
     が profiles.plan を引き直す。**強い方を採る**（`higherPlan`）ので webhook 未着で
     profiles.plan がまだ free でも戻らない
   - **復元直後**: paywall `doRestore()` → `restore()` → free 以外なら同じ `applyEntitlement`
   - **アプリ再起動**: 最初の useGate マウントで profiles.plan と RC `currentPlan()` を並行取得し
     強い方を採用。RC SDK のキャッシュが効くのでオフラインでも「再起動直後に広告が一瞬出る」
     ことがない。webhook が落ちていても entitlement 側で救われる
   - **クーポン**: 従来どおり `refreshGate()`（サーバー値のみ変わる）
   - jest: `src/lib/__tests__/ads.test.ts`（純関数）と `src/__tests__/adSlot.test.tsx`
     （gate → AdSlot の結合・上記3ケース）

## インタースティシャル（全画面広告・2026-09-04 feat/ads-interstitial）

**1箇所だけ**: 概要タブのメニュー行（またはきょうのハイライト）から**詳細へドリルダウンする
瞬間**。ユーザーが自分で次の画面へ進む区切り＝Google 自身が推奨する挿入位置
（natural transition point）で、「起動直後」「戻るボタンの直後」のような禁止例には当たらない。

部品は2層: `lib/interstitial.ts`（**純関数**・出す条件と対象キーの表・jest 23件）→
`lib/interstitialAd.ts`（事前ロード・表示・履歴の読み書き・`useInterstitial()`）。
画面側（`app/(tabs)/changes.tsx`）は遷移を先に確定させてから `interstitial.maybeShow(key)`
を呼ぶだけ。

### 表示条件（すべて満たすときだけ出す・AND）

| # | 条件 | なぜ |
|---|---|---|
| 1 | `shouldShowAd(active, plan)`＝課金有効ビルド × 無料プラン | 有料の「広告なし」は本当の差。**RCキー未設定の現運用では常に false ＝誰にも出ない** |
| 2 | 行き先が `INTERSTITIAL_TARGETS` で true | 医療・機微・読み物の前には出さない（下の表） |
| 3 | **事前ロード済み**（`adLoaded`） | ロード待ちで遷移を止めないため。未ロードなら何も起きなかったのと同じ |
| 4 | アプリ起動から **30秒**以上（`INTERSTITIAL_WARMUP_MS`） | 起動直後の全画面は審査の頻出リジェクト理由。UX上もアンインストールに直結 |
| 5 | **同一セッション（プロセス）で1回**まで | セッションフラグはモジュールスコープ＝タブ再マウントで抜け道を作らない |
| 6 | 前回表示から **10分**以上（`INTERSTITIAL_MIN_GAP_MS`） | 概要タブを行き来する人＝よく使う人に連続で出さない |
| 7 | 今日 **3回**まで（`INTERSTITIAL_MAX_PER_DAY`） | AdMobポリシーと体験の両立。履歴は AsyncStorage `bl-interstitial`（`{date, count, lastMs}`・JST日付でリセット） |

### 絶対にやらないこと（審査リジェクトと信頼喪失の防止）

- **遷移をブロックして広告を待たせる**。`maybeShow` は同期的に判定して即 return するだけで、
  `show()` も await しない。呼び出し側は `setDetailKey` / `router.push` を**先に**実行する
- **記録・保存・課金の操作直後に出す**。トリガーは概要タブのドリルダウンのみ。
  王冠からペイウォールへ飛ぶ分岐（`crownBlocks`）では呼ばない
- **重要な読み物や手続きの前に出す**。法則の解説記事（`laws` → `/laws`）・栄養ランキング図鑑
  （`nutrients`）・受診用PDF・アカウント削除の前には出さない
- **閉じるボタンが出る前に何かを進める**。遷移は広告より先に完了しているので、閉じた時点で
  目的の画面がもう下にある。`AdEventType.CLOSED` でやるのは「広告なしで使えます」の提示だけ
- **リトライしない**。ロード失敗（在庫なし・通信断）はそのセッションでは諦める＝遷移のたびに
  失敗リクエストを積まない

### どのドリルダウンで出すか（`INTERSTITIAL_TARGETS`・1か所の定数表）

線引きの基準は「**その画面を開く動機が、広告1枚をはさんでも損なわれないか**」。
数字のふりかえり（自分の記録を眺めに行く）は途中に広告が入っても目的が変わらない。
医療・機微・読み物は「いま読みたい／いま見たい」が目的そのものなので、広告をはさむと
機能の価値ごと壊す（＝課金してほしい機能の印象まで下げる）。

| 詳細キー | 行の名前 | 出す | 理由 |
|---|---|:---:|---|
| `body` | 体の記録 | ✅ | 体重・グラフ・表の振り返り。最も開かれる行＝収益の主戦場 |
| `volume` | 運動の量 | ✅ | 週の運動量の振り返り。開く動機は「眺める」 |
| `strength` | 筋トレの成長 | ✅ | 自己ベスト・挙上重量の推移。同上 |
| `week` | 週のふりかえり | ✅ | 週1回程度の頻度＝体験を壊しにくい（行き先は `/weekly-review`） |
| `eating` | 食べ方の分析 | ❌ | 過食の引き金カードを含む。「なぜ食べすぎたか」を見に来る人の心理状態に全画面をぶつけない（L4=優しさ） |
| `vitals` | バイタル | ❌ | 血圧・体温など**医療的文脈**。健康の数字を見る前に広告は不適切 |
| `cycle` | 生理周期 | ❌ | **機微情報**。開くこと自体がプライベートな行為 |
| `photos` | 体の写真 | ❌ | **機微情報**＋撮影フロー（操作の途中）に入る導線でもある |
| `nutrients` | 栄養ランキング | ❌ | 図鑑＝**読み物**。`laws` と同じ扱い |
| `laws` | あなたの法則 | ❌ | 法則の**解説記事**（明示的に false を書いて意思を残す） |
| `health` | 歩数・睡眠 | ❌ | HealthKit の許諾ダイアログと重なると何を許諾しているか分からなくなる |
| `bulkguard` / `cycles` | リーンバルク・ガード / サイクル比較 | ❌ | 表示条件が限定的で母数が小さい。収益にならないのに「見るたび広告」の印象だけ残る |

**未知のキー（将来足す行）は既定で出さない**。出したくなったら
`lib/interstitial.ts` の表に明示的に `true` を書く＝意思を持って足す
（jest が「true のキーは body/strength/volume/week の4つ」を見張っているので、
黙って増えることはない）。

### 熊田さんの作業: インタースティシャル・ユニットの作成

1. https://admob.google.com → 左メニュー「アプリ」→ **すでに登録済みの BodyLoger（iOS）**を選ぶ
2. 「広告ユニット」→「広告ユニットを追加」→ 広告フォーマットで **「インタースティシャル」**を選ぶ
   （リワードではない。リワードは「見たら報酬」の約束が必要で、この設計には合わない）
3. 名前は `interstitial-ios` のように分かる名前にする。詳細設定は既定のままでよい
   （広告タイプ＝テキスト・画像・動画すべて／フリークエンシーキャップはアプリ側で
   3回/日に絞っているので AdMob 側では設定しなくてよい）
4. 出てきた `ca-app-pub-…/…`（**スラッシュ**形式）をコピー
   - AdMob の完了画面にはIDが2つ並ぶ。**波線 `~` はアプリID**（app.json に設定済みなので不要）、
     **スラッシュ `/` が広告ユニットID**。取り違えると広告が出ない
5. **Android のアプリでも同じ手順**でもう1つ作る（`interstitial-android`）
   - iOSアプリの下でもう1つ作っても Android では機能しない。**必ずアプリを切り替えてから**
6. Codemagic の環境変数に2つ追加:
   - `EXPO_PUBLIC_ADMOB_INTERSTITIAL_IOS`（iOSアプリのインタースティシャル・ユニットID）
   - `EXPO_PUBLIC_ADMOB_INTERSTITIAL_ANDROID`（Androidアプリの同ID）
   - Secure（暗号化）は不要。公開アプリに埋め込まれる識別子で秘密ではない
7. **再ビルド**（環境変数はビルド時に焼き込まれる。capability変更なし＝自動署名のまま通る）

**設定しなくても壊れない**: 環境変数が空なら `interstitialUnitId()` が null を返し、
広告インスタンスを作らない＝全画面広告は一切出ない（ドリルダウンは普通に動く）。
`__DEV__`（開発ビルド）では Google 公式のテストIDを使うので、実機の開発ビルドで
挙動の確認ができる（実ユニットの無効トラフィックにならない）。

## 広告 → 課金の導線（2026-09-04）

「広告をなくしませんか？」の提示は、広告そのものより繊細に扱う。誇張すれば嘘になり、
罪悪感を誘えば戦略（docs/STRATEGY.md の「静かな伴走者」）に反する。
そこで扱うのは**事実（見た回数）だけ**にし、判定を `lib/ads.ts` の純関数に集約した。

### 出す瞬間は3箇所だけ

| # | 場所 | 何を出すか | 実装 |
|---|---|---|---|
| 1 | **全画面広告が閉じ切った直後**（いちばん効く瞬間） | 控えめなスナックバー「広告なしで使えます →」。約6秒・×で閉じる・タップで `/paywall?src=ads_after` | `components/AdPitchSnackbar.tsx`（`useAdPitch`）を `useInterstitial({ onClosed })` から呼ぶ |
| 2 | **バナーの上の行**（常設・広告ビューの外側） | 「広告を消す →」→ `/paywall?src=ads` | `components/AdBannerView.tsx` |
| 3 | **ペイウォールの先頭**（1・2から来たとき） | 「この1週間で広告を{n}回見ています。スタンダードなら0回です。」 | `app/paywall.tsx`（`shouldShowImpressionCount`） |

### AdMobポリシー上やってはいけないこと（配信停止のリスク）

- **広告ビューに重ねない**。スナックバーは `AdEventType.CLOSED`（閉じ切ったあと）に
  アプリ側のUIとして出る。バナーの導線行は BannerAd の**外**の行
- **広告の閉じるボタンを模倣しない**。バナーの上に × や「閉じる」を置くのは違反。
  消す手段は「課金する」だけで、その導線をリンク1本に集約している
  （押しても消えない偽の × はユーザーへの裏切りでもある）。
  スナックバーの × は自分を閉じるだけで、広告の × とは位置も見た目も無関係（faint の小さな ×）
- **広告の表示を妨げない**。広告が出ている間はこれらのUIは存在しない
- **クリックを誘導しない**。広告の近くに「タップ」「詳しくは」等を置かない
  （「広告」ラベルは faint のまま＝広告表示より導線を目立たせるが、広告の中身には触れない）

### 煽らない文言規約

やること:
- **事実だけ**を言う。「広告なしで使えます」＝プランの説明であって、広告への文句ではない
- 広告除去を**単体で売らない**。`ads` / `ads_after` の lead はどちらも
  「広告が消えて、AIの解析回数もぐっと増えます」＝機能価値と束ねる
  （広告除去単体は訴求として弱く単価が上がらない。プラン表の1行目も「広告なし」）

やらないこと（jest `lib/__tests__/adPitch.test.ts` 22件で固定）:
- **禁止語**: 「我慢」「邪魔」「うんざり」「しつこい」など、広告を悪者にして罪悪感を誘う語
- **「あと◯回で…」のような焦らせ方**
- **エスカレーション**: 回数に応じて文言を強めない（原文テンプレートは1本だけ＝
  n の値で分岐していないことをテストで確認している）
- 回数行は **3回未満では出さない**（`AD_PITCH_MIN_IMPRESSIONS`）。1〜2回で
  「たくさん見ています」と言うと嘘っぽくなり、かえって信用を失う
- 提示は **1日2回まで**（`AD_PITCH_MAX_PER_DAY`）。全画面広告は1日3回まで出るので、
  **勧誘は必ず広告より少ない**（テストで `< 3` を固定）

### 見た回数の数え方（端末内のみ）

- AsyncStorage `bl-ad-impressions`＝直近7日ぶんの `{date, count}` 配列
  （`bumpImpression` / `weeklyImpressions`・純関数）。7日より古い行は落とす
- 加算は**バナーの読み込み成功時**（`AdSlot` の `onLoaded`）と**全画面広告の表示時**。
  同じ枠の30秒以内の重複（タブ往復・再レイアウト）は数えない＝ユーザーに見せる数字を水増ししない。
  未来日付も数えない（端末の時計をいじっても増えない）
- AsyncStorage `bl-ad-pitch`＝「広告なしで使えます」の提示回数（`{date, count}`・JST日でリセット）
- **サーバーへは送らない**。広告の見え方は端末とプランで決まるので集約する必要がなく、
  送らなければプライバシー上の説明も要らない

### 点火前は全部眠っている（嘘をつかない）

`shouldPitchAdRemoval` / `shouldShowImpressionCount` の第1条件が
`shouldShowAd(active, plan)` なので、**RCキー未設定の現運用では誘導も回数行も一切出ない**。
広告が1枚も出ていない人に「広告を消せます」と言わない＝広告と課金の点火が同時になる
（バナー・全画面・導線がすべて同じ1つのスイッチにぶら下がっている）。
課金者（lite/standard/premium）にも当然出ない。

## 将来 placement ごとにユニットを分けるとき

1. AdMob 管理画面で iOS/Android それぞれに「バナー」ユニットを追加（名前は
   `banner-ios-training` のように placement を含める）
2. `components/AdBannerView.tsx` の `bannerUnitId(m, placement)` で placement ごとに ID を
   返す（`PROD_BANNER` を `Record<AdPlacement, {ios, android}>` にする）。呼び出し側の
   変更は不要（AdSlot が placement を渡している）
3. 環境変数で差し替える場合は `EXPO_PUBLIC_ADMOB_BANNER_IOS_<PLACEMENT>` の命名で追加し、
   未設定なら共用IDへフォールバックさせる（片方だけ設定しても壊れないように）
4. 再ビルド（ユニットIDはビルド時に焼き込まれる）
5. 分ける動機は「枠ごとの eCPM/表示率を見たい」ときだけ。分けなくても placement は
   コード上で区別できているので、計測だけなら AdMob のカスタムイベントより先に
   自前ログ（analytics）に placement を送る方が安い

## ID は2種類ある（混同注意）

| 種類 | 形式 | どこに設定するか |
|---|---|---|
| **App ID**（アプリごと・iOS/Android別） | `ca-app-pub-XXXX~YYYY`（チルダ） | `native/app.json` の plugin 設定（要再ビルド） |
| **広告ユニットID**（バナーごと） | `ca-app-pub-XXXX/YYYY`（スラッシュ） | Codemagic 環境変数（要再ビルド） |

現在は **どちらもGoogle公式のテストIDが仮置き**されている:

- App ID（app.json）: iOS `ca-app-pub-3940256099942544~1458002511` / Android `~3347511713`
- バナーユニットID: 環境変数未設定のためコードが `TestIds.ADAPTIVE_BANNER` にフォールバック

**テストIDのままでも広告の表示・レイアウト確認は完全にできる**（「Test Ad」ラベル付きの
本物の広告が出る）。収益が発生しないだけなので、実ID取得前にTestFlightで見た目の確認が可能。

## 熊田さんの手順（実IDへの差し替え）

1. **AdMobアカウント作成** — https://admob.google.com （Googleアカウントで無料。
   支払い情報は収益発生後でOK）
2. **アプリを2つ登録** — AdMob管理画面「アプリ」→「アプリを追加」。
   iOS用とAndroid用で別々に登録する。ストア未公開でも
   「アプリはストアに掲載されていますか？→いいえ」で**手動登録**できる
   （公開後にストアと紐付け直せる）
3. **App ID×2 を app.json へ** — 各アプリの「アプリ設定」に出る
   `ca-app-pub-…~…`（チルダ形式）を `native/app.json` →
   `plugins` → `react-native-google-mobile-ads` の `iosAppId` / `androidAppId` に差し替え
4. **バナー広告ユニットを作成** — 各アプリで「広告ユニット」→「バナー」を1つずつ作成。
   出てきた `ca-app-pub-…/…`（スラッシュ形式）を **Codemagic の環境変数**へ:
   - `EXPO_PUBLIC_ADMOB_BANNER_IOS`（iOSアプリのバナーユニットID）
   - `EXPO_PUBLIC_ADMOB_BANNER_ANDROID`（AndroidアプリのバナーユニットID）
   - インタースティシャル（全画面）は**別のユニット**を作る必要がある。手順は
     「インタースティシャル（全画面広告）」節の「熊田さんの作業」を参照
     （`EXPO_PUBLIC_ADMOB_INTERSTITIAL_IOS` / `_ANDROID`）
5. **再ビルド** — App ID・環境変数はどちらもビルド時に焼き込まれるため、
   差し替え後は必ず再ビルド（capability変更なし＝Codemagicの自動署名でそのまま通る）

## 注意（アカウント停止事由）

- **実IDの広告を自分でタップしない**（テスト目的でも不可）。動作確認はテストIDで行うか、
  AdMob管理画面で自分の端末を「テストデバイス」に登録してから行う
- 実IDに差し替えた直後は「広告在庫の準備中」で数時間〜数日出ないことがある（正常）
