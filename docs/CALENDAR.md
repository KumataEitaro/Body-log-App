# カレンダー連携 設計案 — 2026-09-03

**未実装・設計のみ。** docs/STRATEGY.md の N1「今日の予定ヒアリング」を、**手動の1問から
「聞かずに分かる」へ**引き上げる自動化レイヤー。戦略ゲート①（摩擦を減らす）③（次の行動）⑤（明日開く理由）に効く。

## 0. なぜやるか / やらないか

N1（実装中）は朝に1問だけ聞く。答えれば夜の外食を見込んで朝昼を再配分できる。
しかし**聞かれること自体が摩擦**であり、答えない日は再配分が効かない。
カレンダーを読めば「今日19時に歓送迎会」が**聞かずに分かる**＝伴走者として一段上がる。

一方、カレンダーは**極めて機微**（通院・面接・誰と会うか）。設計を誤れば「監視されている感」で
一気に信頼を失う。したがって**端末内だけで処理し、タイトルは保存もAI送信もしない**ことを絶対条件にする。

## 1. 技術要件（確認済み）

- `expo-calendar`（未導入。SDK 57 対応版を `npx expo install expo-calendar` で追加）
- **iOS 17+ で権限が分割**された。読み取りには `NSCalendarsFullAccessUsageDescription` が必要
  （`WriteOnly` では**読めない**）。旧 `requestAccessToEntityType` は非推奨で、
  `requestFullAccessToEvents` 系に置き換わっている（Expo SDK 54/55 で対応済み）
- **provisioning profile の capability は不要** → 署名・プロファイルは壊れない
  （HealthKit や Associated Domains とは種類が違う。2026-09-03のビルド失敗とは無関係）
- Android も同一APIで読める（`READ_CALENDAR`）。Expo Go では権限ダイアログが出るがビルド不要
- app.json に追加するもの:
  ```
  ios.infoPlist.NSCalendarsFullAccessUsageDescription:
    "外食や飲み会の予定を読み取り、その日の食事プランを自動で調整するために使います。予定の件名が端末の外に出ることはありません。"
  plugins: ["expo-calendar", { calendarPermission: 同文 }]
  ```

## 2. プライバシー設計（これが本体）

| 原則 | 実装 |
|---|---|
| **既定OFF** | 設定＞「カレンダーから予定を読む」トグル。ONにした瞬間だけ権限を要求する（起動時に勝手に聞かない） |
| **読むカレンダーを絞る** | 端末のカレンダー一覧から**本人が選んだものだけ**（仕事用だけ除外したい人がいる）。既定は「選択なし＝読まない」 |
| **読む範囲を絞る** | 今日（と翌日の0〜2時）のイベントのみ。終日イベントは無視（食事時刻が決まらない） |
| **タイトルを保存しない** | 件名は**その場の確認ダイアログに表示するだけ**。AsyncStorage・Supabase・ログのいずれにも書かない。保存するのは `{kind, at, estKcal}`（N1と同じ形）だけ |
| **AIに送らない** | Gemini へのプロンプトに件名を含めない。「今日は外食の予定あり」という**種別と時刻だけ**を渡す |
| **勝手に決めない** | 検出したら必ず1回確認する: 「19:00に『歓送迎会』があります。飲み会として見込みますか？」→［見込む］［今日は普通の食事］［今後この予定は聞かない］ |
| **App Storeの申告** | 端末外に出さない＝Appleの定義では **collection に当たらない**ためプライバシーラベルの申告は不要。ただし usage description は必須。「端末の外に出ない」ことを文言に明記して審査の疑問を先に潰す |

## 3. 判定（端末内辞書・content/calendarKeywords.ts）

| 種別 | キーワード例（部分一致・日本語＋英語） |
|---|---|
| 飲み会 | 飲み会・歓送迎会・懇親会・打ち上げ・忘年会・新年会・二次会・party・drinks |
| 外食 | 会食・ランチ・ディナー・ご飯・食事会・lunch・dinner・BBQ・焼肉・寿司 |
| トレーニング | ジム・トレーニング・パーソナル・ランニング・練習・gym・workout・run |
| 除外 | 通院・病院・面接・葬儀・法事 等の**機微語は種別判定しない**（プランに使わない・確認も出さない） |

- 時刻は `startDate` のJST時刻。19時以降なら夕食枠、11〜14時なら昼枠
- 想定kcalの既定: 飲み会1,000／外食800（N1と同じ値・±チップで調整可）
- **誤検知の逃げ道**: 確認ダイアログで「今日は普通の食事」を選べば、その日は何もしない

## 4. 副作用として得られる良い挙動

- **会議中にリマインダーを出さない**: 記録リマインダーの予約時刻にイベントがあれば、
  30分後にずらす（既存の smart モードに乗る）。通知の賢さは継続率に直結する
- 「明日は飲み会だから今日は少し余裕を作る」の**前日予告**（1日前・21時・1件まで）。
  ただしこれは介入が強いので**別トグル**にする

## 5. やらないこと

- 予定の**書き込み**（トレーニング予定をカレンダーに入れる等）。読み取りだけに徹する
- 空き時間から「今なら運動できます」の提案 → 監視感が強く、戦略の「静かな伴走者」に反する
- 参加者・場所の読み取り（食事プランに不要）

## 6. 実装ボリューム

| 部位 | 規模 |
|---|---|
| expo-calendar 導入＋権限フロー＋カレンダー選択UI（設定） | 中 |
| キーワード辞書＋判定（純関数・テスト） | 小 |
| 検出→確認ダイアログ→N1のデータモデルへ流す | 小（**N1完成後なら接続だけ**） |

| 文言・審査用の説明・docs | 小 |
