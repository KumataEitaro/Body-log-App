## A. 課金の整合性（最重要・審査と信頼の両リスク）

### A1. ライトプラン「広告なし」だが、広告が未実装 🔴
- 現状: アプリに広告表示は存在しない（文言だけ）。つまり**ライト¥300は無料と差がゼロ**
- リスク: App Store審査4.3（実体のない課金）/購入者の「何も変わらない」→低評価・返金
- 対処の選択肢: ①広告SDKを入れてからライト解放 ②当面ライトを非表示（スタンダード/プレミアムだけで出す） ③初回リリースは課金自体を出さない（現状のRCキー未設定運用のまま）
- **推奨: ③で公開→広告実装とセットで課金列車を分ける**
- → **広告実装済み（2026-09-01・feat/ads）**: AdMobアンカー型アダプティブバナー・NPA固定・
  useGateでactive×無料プランのときだけ表示（=課金解放と同時点灯が仕組みで保証）。
  残タスク＝AdMobアカウント作成→実App ID/ユニットIDの取得と差し替え（手順: docs/ADS.md）

### A2. AI上限が眠ったまま課金を出すと、スタンダード/プレミアムも実体がない 🔴
- AI_LIMITS_ENABLED=false の間は無料でも無制限＝「AI解析50回/日」を買う理由がない
- **課金解放・王冠表示・AI_LIMITS_ENABLED=true は必ず同時**（3点セット）。バラすと嘘になる

### A3. RC_WEBHOOK_SECRETのローテーション 🔴
- スクショで漏洩済み。課金を有効化する前に必ず再発行（Vercel環境変数とRC側の両方）

### A4. サンドボックスの$表示の確認（既知・TODO4） 🟡

### C3. Android実機の総合未検証 🟡（起動クラッシュは構造対策済み・原因は未特定）
- edge-to-edge対応13箇所は机上修正のみ。内部テスト（自分1人・即配布可）で
  全画面を一巡してから12人テストへ。特に: シート上端・カメラ（バーコード）・
  通知チャンネル・戻るボタンでのモーダル閉じ

**2026-09-03: 初回インストール（1.1.0 / versionCode 119）で起動直後のクラッシュが発生。**
内部テストではPlayのリリース前レポートが生成されず、Android vitalsも反映待ちで
スタックトレースが取れなかったため、**当て推量で1箇所直すのをやめて「落ちない構造にして
原因を記録させる」方向で対処した**（詳細と調査手順は docs/ANDROID.md
「起動クラッシュの調査手順」）。

対処済み:
- 起動時の初期化13本を `safeBoot()`（lib/boot.ts）で1つずつ独立化。
  どれが失敗しても他の初期化とレンダリングを止めない。失敗は端末内
  （AsyncStorage `bl-boot-errors`・最大20件）に残り、設定画面の最下部
  「起動時のエラー記録」から読める＋コピーできる。次回起動時に `crash_reports` へも送る
- 認証が読めないときも必ずログイン画面まで進む（無限スプラッシュを作らない）
- モジュール評価時（ErrorBoundaryより手前）の副作用を全数 try/catch 化（4箇所）
- `Intl.DateTimeFormat` 依存のJST整形を自前の純関数（lib/jst.ts）へ置換。
  ただし **RN 0.86 の hermes-android は `-DHERMES_ENABLE_INTL=True` でビルドされている**
  ことを確認したので（`ReactAndroid/hermes-engine/build.gradle.kts`）、
  「Intlが無くて落ちた」は真因ではない可能性が高い。
  それでも外したのは、Hermesの実装がAppleのICUとは別物でオプション次第でRangeErrorになり、
  有効かどうかをアプリ側から保証できないため（保証できない依存を減らす）
- `EXPO_PUBLIC_SUPABASE_*` がバンドルに埋め込まれていない場合、`createClient` が
  モジュール評価中に throw して JSバンドル読み込み中に死ぬ経路を塞いだ（記録して先へ進む）

未クローズ（残っているリスク）:
- **原因は特定できていない。** 上記はいずれも「落ちない構造」＋「原因を記録させる」対策で、
  真因を直したわけではない。次のビルドでも落ちる可能性はある（そのときは
  「起動時のエラー記録」か logcat に何が出るかで初めて切り分けられる）
- **ネイティブ側（Java/Kotlin/C++）のクラッシュはJS側の対策では止まらない。**
  AdMob SDKの初期化・ネイティブモジュールのリンク・リソース解決の失敗は
  `safeBoot` の外側なので、`adb logcat --buffer=crash` か
  クローズドテストのリリース前レポートを見るしかない
- **リリース前レポートを出すには内部テストではなくクローズドテストへ上げる必要がある**
  （内部テストのままでは何回上げてもトレースが出ない）
- Androidの実機での全画面一巡は依然として未実施（起動できた先の検証がまだ0）

## 追記 2026-09-04: TestFlight のペイウォールが $ 表示だった件

実機（TestFlight・iOS）でペイウォールの価格が `$4.99 / $29.99 / $9.99 / $69.99` と USD で表示された。

**アプリ側の問題ではない。** `app/paywall.tsx` は価格文字列も通貨コードも StoreKit（RevenueCat の
`pkg.product.priceString` / `currencyCode`）から受け取ってそのまま出しており、`$` を固定で書いていない。
月あたり換算も `currencyCode` を使って `Intl.NumberFormat` で整形している。

通貨は **端末の App Store アカウント（TestFlight では Sandbox アカウント）の国**で決まる。
USD で出た＝その端末で使っていたアカウントのストアフロントが US だった、ということ。
日本のアカウントで見れば ¥ になる。

### 確認手順（A3/A4 の実施そのもの）
1. https://appstoreconnect.apple.com → **ユーザーとアクセス → Sandbox → テスター** で
   **国/地域＝日本** の Sandbox テスターを作る（既存のものがあれば国を確認）
2. 端末の **設定 → App Store → サンドボックス アカウント** にそのテスターでサインイン
3. アプリのペイウォールを開き、**¥ 表示**と、App Store Connect で設定した日本の価格と一致することを確認
4. App Store Connect → アプリ → **サブスクリプション → 各商品 → 価格** で、日本（JPY）の価格が
   意図した値になっているか（USD 基準の自動換算のままになっていないか）も確認する
