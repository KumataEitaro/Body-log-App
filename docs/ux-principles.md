# BodyLog UX原則（実装チェックリスト）

新機能・改修は必ずこのリストに照らす。根拠は Apple Human Interface Guidelines（HIG）と
Nielsenの10ユーザビリティヒューリスティクス。「iOSの有名アプリと同じに動く」が合格ライン。

## ナビゲーション
- [ ] **タブ再タップ＝そのタブのトップへ戻る**。トップにいる時の再タップ＝最上部へスクロール（HIG標準・AppShellで共通実装済み）
- [ ] サブ画面には必ず**大きい戻る導線**（BackBar・タップ領域44px以上）。小さいテキストリンクを戻るに使わない
- [ ] 端末の「戻る」操作（スワイプ/ブラウザバック）でも同じ場所に戻れる（状態はURLに持たせる）
- [ ] 今どのタブにいるかが常に分かる（サブ画面でも親タブをアクティブ表示）

## タッチ・操作
- [ ] タップ対象は**最小44×44pt**（HIG）。×ボタン・チップの−なども例外にしない
- [ ] 破壊的操作（削除・上書き）は確認を挟むか取り消し可能にする
- [ ] 押した感触を返す（:activeのスケール・ハプティクス）。無反応に見える瞬間を作らない
- [ ] スクロール中に要素が動いて誤タップさせない（並び替えは表示中に発動しない）

## 状態の見える化（Nielsen #1）
- [ ] 処理中はスピナー/スケルトンを即時表示（体感1秒以上待たせるなら必ず）
- [ ] 保存・成功は明示的にフィードバック（トースト＋ハプティクス）
- [ ] オフライン・未同期・未記録など「システムの状態」を隠さない（⏳未同期・?未記録の思想）

## エラー（Nielsen #9）
- [ ] ユーザー向けは短い日本語のみ（選択言語へ自動翻訳が効く80字以内）。英語の生エラーを出さない
- [ ] 「何が起き、次に何をすればよいか」を必ず書く。責めるトーン禁止
- [ ] 技術詳細はconsole/サーバーログへ（診断画面で確認可能に）

## 入力の負荷
- [ ] 入力は1画面1目的。よく使う操作ほどタップ数を減らす（チップ・プリセット・前回値プリフィル）
- [ ] キーボード種別を内容に合わせる（数値はinputMode）。フォント16px以上でiOSの勝手ズームを防ぐ
- [ ] ユーザーが書いた内容を勝手に消さない（エラー時も入力を保持して戻す）

## 正直さ（BodyLog固有の思想）
- [ ] データが足りない時は黙る/「あと◯日分」と言う。無い根拠で断定しない
- [ ] 相関と因果を混同させない注記。n数を添える
- [ ] 未記録・不明を0や平均で塗りつぶして隠さない（±0扱いは明示する）
