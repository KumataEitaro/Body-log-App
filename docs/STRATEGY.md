# BodyLoger プロダクト戦略（正本）— 2026-09-03

熊田さんの戦略整理をそのまま正本として置く。**新機能の採否は §4 のゲートで判断する。**

## 1. 中心命題

> **「ユーザーに記録させる」のではなく、「ユーザーが自分の身体について迷う時間を減らす」。**

進化の順序: **Logging App → Decision App → Companion**。
目指すのは「食事を記録するアプリ」ではなく「身体づくりを毎日一緒に考えてくれるAI伴走者」。
開く理由が「記録しなきゃ」では弱い。**「今日どうすればいいかBodyLogerに聞こう」**が到達点。

## 2. 最重要KPIは機能数ではなく継続率

機能追加→価値向上、と単純には考えない。
**ユーザーが戻ってくる理由 → 継続率 → LTV → 課金ユーザー数・売上** の順で考える。
本質は `CAC < LTV`。1万人集めることより、その1万人が何ヶ月残るか。

## 3. 継続を生む4要素

| # | 要素 | 具体 |
|---|---|---|
| ① | 摩擦を減らす | 「鶏胸200g、ご飯180g、味噌汁」だけで記録できる。完璧な入力を要求しない |
| ② | 成長を感じさせる | 「今日は1,940kcal」で止めない。「直近7日で約2,100kcalの赤字。このペースなら順調」まで返す |
| ③ | 次の行動を教える | 「タンパク質があと35g不足。夜は脂質を抑えてタンパク質を」まで出す。**Log → Understand → Act** を1つのUXに |
| ④ | 感情的報酬 | 採点しない。**昨日崩れても、今日また戻ってこられる場所**。Streakより **Comeback** を重視 |

## 4. 新機能の判断ゲート（Claude Codeはこれで評価する）

1. 記録の摩擦を減らすか
2. 自分の身体への理解が深まるか
3. 次の行動が分かるか
4. 成長実感が得られるか
5. **明日もう一度アプリを開く理由になるか**

どれにも該当しない機能は原則として優先順位を下げる。
**問いは「新しいことができるか」ではなく「明日開く理由になるか」。**

## 5. AIの人格

トレーナーでも先生でも監視者でもない。**知識のある、静かな伴走者**（Non-Judging Companion）。

- ❌「脂質を取りすぎています！」 → ⭕「今日は脂質が少し高め。夕食を軽めにすれば十分調整できます」
- ❌「目標を達成できませんでした」 → ⭕「今日はこんな日。1週間単位ではまだ問題ありません」
- ❌「3日間記録していません」 → ⭕「今日からまた記録すればOK」

## 6. 理想的な1日（朝→昼→夜→週末）から逆算する

- **朝**: 大量の数字ではなく「今日をどう過ごせばいいか」を最初に見せる。＋AIから必要な情報だけ**1問**聞く（「今日は外食の予定ありますか？」）。回答で**その日のプランを動的に変える**
- **昼**: 「腹減った。コンビニ行く」→ 残量と不足を踏まえて**次に何を食べればいいか決めてくれる**
- **夜**: 「ラーメン食べたい」→ 禁止せず**選択した結果を見せる**（今日/今週/予測体重）
- **週末**: 数字を並べず「前進している感覚」＋**来週の目標を1つだけ**

## 7. 現状実装との差分（2026-09-03・v1.1.0時点）

### ✅ すでに実装済み（戦略の主要部分は形になっている）
- ①摩擦: つぶやき入力・写真・マイ食品（単品/セット）・＋ボタン2段シート・食べた時間チップ・オフラインキュー
- ②成長: **週間・月間の収支カード**（「体重は週と月の合計で決まる」の原理提示）・トレンド2期間平均・あなたの法則17種＋科学的裏付けの解説記事
- ③行動: **「何を食べる？」**（コンビニ/外食/自炊/間食/時間がない → 3案 → これにする→記録）・**気づきアラート**（法則駆動の事前警告＋ポジティブ側）・スマート置き換え・栄養ランキング・たんぱく源ティア
- ④感情: **おかえりフロー**（「◯日空いた」と絶対に言わない）・非審判トーンの安全ガード・バッジ（メダル＋遡及通知）・お守り炎
- 未来の一部: **チートデイ登録**（超過分を前後の日で自動吸収・前日20時通知）＝「予定を知って再配分する」原型
- 週末: 週のふりかえり（記録日数・平均摂取の先週比・平均収支・体重変化）

### ⏸ 保留（理由つき）
- **ファネル計測基盤**（Impression→…→Paid）: 戦略上は Phase 1 の前提だが、独自の利用状況イベントを足すと**App Storeのプライバシーラベル申告に「使用状況データ」が増える**（提出直前の申告変更＝リスク）。**1.1.0提出後**に、App Store Connectの標準指標（Impression/Install/Retention）＋Vercel Analytics＋自前の最小イベントで組む。それまでは端末内カウンタで代替
- 広告出稿: 「壊れたファネルを救うものではなく、機能しているファネルを増幅するもの」。ASO→ストアページ→Activation→Retention の改善後に小額で**メッセージ検証装置**として使う

## 9. 開発サイクル
