# AI（LLM）プロバイダの選定と乗り換え設計

最終更新: 2026-09-15。価格の実地調査は `docs/llm-pricing-2026-09.md`（全社の公式ページを 2026-09-15 に確認）。

## なぜこの文書があるか

2026-09-15 に **AI が全断した**。Gemini のプリペイド残高が尽き、全モデルが
`HTTP 429 Your prepayment credits are depleted` を返した（調べ方は docs/PROJECT-STATUS.md）。
熊田さんの要望は「**叩く先のアドレスが無くなるかもしれないので変更したい。安いモデルを提案して**」。

調べた結論は、**費用より先に片付けるべき問題が1つある**というものだった。以下その順で書く。

## 1. 最優先: 無料枠のままではプライバシーポリシーに違反している 🔴

これは費用の話ではない。**公開前に必ず直す。**

Google の公式規約（https://ai.google.dev/gemini-api/terms ・2026-09-15 確認）:

| | 無料枠（Unpaid Services） | 有料枠（Paid Services） |
|---|---|---|
| 学習・製品改善 | "Google uses the content you submit to the Services and any generated responses to **provide, improve, and develop Google products**" | "Google **doesn't use** your prompts...or responses to improve our products" |
| 人間によるレビュー | "**human reviewers may read, annotate, and process** your API input and output" | 安全性の違反検知のために限定期間ログするのみ |

いま BodyLoger が Gemini へ送っているもの:

| 経路 | 送るもの | ファイル |
|---|---|---|
| `/api/parse-food` | 食事のテキストと**食事の写真**（最大4枚） | `native/src/app/(tabs)/log.tsx` |
| **`/api/analyze-body`** | **体の写真**（体組成の推定・前後比較） | `native/src/components/BodyPhotosCard.tsx:106` |
| `/api/coach` | 体重推移・摂取・気分・**制約プロフィール（アレルギー・宗教/ベジ・妊娠授乳中）** | `native/src/app/(tabs)/coach.tsx` |

一方、`app/privacy/page.tsx` で利用者にこう約束している:

> 目的外の第三者提供は行いません。……ヘルスケアデータをAI解析（Google Gemini）へ送信する場合も、
> **上記の機能提供の目的に限られます**。

**無料枠の規約とこの約束は両立しない。** 体の写真を「Google の製品改善のために人間が見ることがある」状態で
「機能提供の目的に限られます」とは言えない。有料枠に切り替えれば規約側が「製品改善に使わない」になり、約束と一致する。

> 補足: 無料枠はレート制限も低く、残高切れとは別に全断の原因になる。
> **有料枠化は、規約・可用性・今回の事故の3つを同時に解決する**。

## 3. 結論: モデルは変えない。乗り換えられる形にする

### ⚠️ 3-0. 2026-09-15 夕方の実測で 3-1 の前提が崩れた（読み替え必須）

個人アカウントで**作り直したプロジェクトの鍵**で全モデルを叩いたところ:

| モデル | 結果 | 単価 |
|---|---|---|
| `gemini-2.5-flash-lite` | ❌ **404 “no longer available to new users”** | $0.10/$0.40（もう使えない） |
| `gemini-2.5-flash` | ❌ 404 同上 | — |
| **`gemini-3.1-flash-lite`** | ✅ 200（約0.9〜1.0秒） | **$0.25/$1.50** ← 実測で通る最安 |
| `gemini-3.5-flash-lite` | ✅ 200（`thinkingConfig` は400で拒否・自動で外して再試行される） | $0.30/$2.50 |
| `gemini-flash-lite-latest` | ✅ = `gemini-3.5-flash-lite` の別名 | $0.30/$2.50 |
| `gemini-flash-latest` | ✅ = **`gemini-3.8-flash`** の別名 | $0.75/$3.75 → **2027-01-01 に倍増** |

**つまり「2.5-flash-lite のまま」は選べない。** 一次は **`gemini-3.1-flash-lite`** になった。

さらに `rank()` が lite に -6 のペナルティを付けていたため、放置すると**自動的に最も高い**
`gemini-flash-latest`(=3.8-flash) が選ばれ続ける状態だった。2026-09-15 に **lite を +40 に反転**して修正済み。

**費用の見直し**（テキスト1回・入力5,000のうち2,500キャッシュ・出力500）:

| モデル | 1回 | 1,000人規模の月額 |
|---|---|---|
| （旧）`gemini-2.5-flash-lite` | $0.00048 | 約 $85 |
| **（現）`gemini-3.1-flash-lite`** | **$0.00144** | **約 $260** |
| **`gpt-5-nano`** | **$0.00034** | **約 $61** |

→ **`gpt-5-nano` が、使える Gemini のどれよりも 4.2倍安くなった。**

二次に Gemini を残せば会社1社への依存も同時に解ける。判断材料は B17 の日本語精度の実測。

### 3-1. 一次: `gemini-2.5-flash-lite`（現状維持＋有料枠化） ※ 2026-09-15 に前提が崩れた（上記 3-0 を参照）

$0.10 / $0.40・キャッシュ読み $0.01。写真5枚込みの実効コスト **$0.00077/req** で最安クラス。
画像は 1,032トークン/枚と効率がよく（Together の1/6）、JSON はスキーマで強制でき、廃止告知も無い（2026-09-15時点）。
**コード変更ゼロ**で、いま動いているものがそのまま最適解。**やることは有料枠への切り替えだけ。**

> ⚠️ Gemini 3.x へ急いで移らないこと。3.6/3.7/3.8 Flash は **2027-01-01 に単価2倍が公式告知済み**
> （$0.75→$1.50 / $3.75→$7.50）で、2.5-flash-lite の 7.5〜15倍になる。
> 移るなら `gemini-3.1-flash-lite` ＋ `media_resolution: "medium"`（既定の 1,120 のままだと画像費用が倍）。

### 3-2. 二次（待機系）: `gpt-5-nano`

$0.05 / $0.40・キャッシュ読み $0.005。実効コスト **$0.00068/req** で、**Gemini をわずかに下回る**。
画像パッチは Gemini の1.7倍重いが、入力単価が半分なので相殺される。

選ぶ理由は価格ではなく**乗り換えやすさ**:

- **OpenAI 互換の本家**。Gemini 自身が OpenAI 互換エンドポイント
  `https://generativelanguage.googleapis.com/v1beta/openai/` を持つので、
  **両者は `baseURL` と `model` の差し替えだけで入れ替わる**
- vision ✅ / `json_schema` strict ✅ / 400Kコンテキスト / 1リクエスト1,500枚
- 日本リージョン `jp.api.openai.com` あり（regional storage）
- 旧モデルを長く残す傾向で、存続リスクが調査対象中で最も低い

### 3-3. 三次（欧州系の第3極・保留）: `ministral-8b-2512`

$0.15 / $0.15 で**入出力が同額**。出力が多い用途に有利。OpenAI 互換。
ただし**画像のトークン換算式が公式に未記載**で実効コストが見積もれず、レート制限も非公開。
採用するなら実測が先。**いまは候補に留める。**

### 3-4. 落とした候補と理由

| 候補 | 落とした理由 |
|---|---|
| **Groq** | vision が**1リクエスト最大3枚**。食事写真4枚の要件を満たさない |
| **Anthropic**（OpenAI 互換経由） | `response_format` が**エラーにならず黙って無視される**＝JSON を強制できない。ネイティブ実装が別途必要になり多重化コストが一段上がる。実効コストも Gemini の**14倍** |
| **Together AI** | 入力 $0.17 と安く見えるが**タイル課金が1枚6,404トークン**。実効で Gemini の**8倍** |
| **DeepSeek** | peak 時間帯が **JST 10-13時・15-19時**で、食事記録アプリのピークと完全に重なる。実効単価は peak 側（Gemini の2.9倍）で見るべき |
| **Moonshot / Kimi** | 調査対象中で**モデル廃止が最も激しい**（`moonshot-v1-*` 8種が 2026-08-31、`kimi-k2` 系が 2026-05-25 に廃止済み） |
| **xAI** | 画像のトークン換算式が公式に一切なく、費用を見積もれない |
| **Qwen の vision** | `json_schema` strict 非対応（`json_object` のみ） |
| **OpenRouter** | 単価マークアップは無く魅力的だが、**それ自体が新たな単一障害点**になる。最終フォールバックとしてなら可（採用時は `provider.require_parameters: true` と `provider.data_collection: "deny"` が必須） |

## 4. 乗り換えられる形にする（実装設計）

### いまの構造

Gemini 固有の記述は **`lib/gemini.ts` の中の12行だけ**で、残り300行は
「モデル発見・追い越しヘッジ・失敗ペナルティ・再試行」という**プロバイダに依存しない可用性の仕掛け**。
呼び出し側は9か所すべて同じ形 `callGemini(key, parts, temperature)`。
**アプリ（native）は API 経由でしか AI に触らないので、サーバだけ直せばよく、再ビルドは不要。**

| Gemini 固有 | 中身 |
|---|---|
| エンドポイント | `https://generativelanguage.googleapis.com/v1beta` |
| 認証 | `?key=` クエリ |
| リクエスト | `{ contents: [{ parts }], generationConfig: { responseMimeType, thinkingConfig } }` |
| 画像 | `{ inline_data: { mime_type, data } }` |
| レスポンス | `j.candidates[0].content.parts[].text` |
| モデル発見 | `GET /v1beta/models` |

### 目指す構造

```
lib/llm/
  types.ts        Part / LlmResult（いまの型をそのまま移す）
  openaiCompat.ts /v1/chat/completions を話すクライアント（OpenAI・Gemini互換・DeepSeek・Mistral・xAI…が全部これ）
  geminiNative.ts いまの実装（モデル自動発見があるので残す価値がある）
  router.ts       プロバイダ横断のヘッジとフォールバック。公開APIは callLlm(parts, temperature)
```

要点:

1. **既存のヘッジ・ペナルティの仕掛けは捨てない。** 1回の試行の「通信部分」だけ差し替え、
   候補の単位を「モデル」から「プロバイダ×モデル」に広げる
2. **env だけで切り替わるようにする。** コードを触らず Vercel の環境変数と再デプロイで乗り換えられる状態が目標
   ```
   LLM_PROVIDERS=gemini,openai        # 左から順に試す
   GEMINI_API_KEY=...
   OPENAI_API_KEY=...
   ```
3. **画像を含むリクエストは vision 対応のプロバイダだけに回す。** 安いテキスト専用モデルを混ぜても壊れないように
4. **JSON 強制の方式はプロバイダごとに違う**（`responseSchema` / `json_schema` / `json_object` / 非対応）。
   既存の `parseJsonLoose` が最後の砦なので、そこは残す
5. 公開APIの名前は `callGemini` → `callLlm` に変えるが、**引数と戻り値は変えない**。9か所の呼び出しは import 名の変更だけ

### プロンプトキャッシュを効かせる前提

OpenAI も Gemini も自動キャッシュだが、**プロンプト先頭からの前方一致**が条件。
いまの `buildParseFoodPrompt` は固定のルール文が先頭に来ていて条件を満たすが、
`outLang` が中盤（45行目付近）に差し込まれるため**言語ごとに別キャッシュ**になる。
可変値（言語・辞書・本人の数値）を**すべて末尾へ寄せる**と、入力費用が 1/10 の単価で効く範囲が広がる。
