# インタラクティブチャート＋C案展開 — 要決定事項の定義書

参照: Appleヘルスケア体重チャートの画面録画（2026-07-28）。
月表示=日次実測点／6ヶ月表示=週平均点＋スクラブで「平均+期間」表示／傾向バッジ／右Y軸自動リスケール。

---

## A. データ・DB整理

| # | 決定項目 | 選択肢 | 推奨 |
|---|---|---|---|
| A1 | データソース | 新集計テーブルを作る / 既存テーブルを使う | **既存で足りる**: 体重・ウエスト=`entries`（日次サマリー、logsから自動集計済み）、体脂肪=`body_photos.bf_est`、摂取kcal=`entries.intake` |
| A2 | 集計（平均）の計算場所 | DBビュー / API / クライアント | **クライアント**。5年分でも約1,800行・数十KB。既存の全件フェッチ＋localStorageキャッシュを流用。DB変更ゼロで高速に動く |
| A3 | 前提マイグレーション | — | **Supabase migration 8〜13 の適用が前提**（特に13=waist列。ウエスト系列を出すなら必須。PFC目標保存も直る） |
| A4 | 欠測日の扱い | 補間する / ギャップ | **ギャップ**（Apple方式）。線は隣接実測点をつなぐが、平均計算は実測値のみ使用 |
| A5 | 日内複数記録の代表値 | 平均 / 最後の値 | **最後の値**（既存summarizeDayの仕様を踏襲） |
| A6 | 丸め | — | 体重・ウエスト0.1、体脂肪0.1%、kcal整数。傾向は±0.1 |

## B. ビン（集計粒度）と平均の定義 — 「どこで平均点を取るか」

**【2026-07-28 更新】ズーム＝連続（ピンチで無段階）、ビン＝窓幅しきい値で多段自動切替。**

| 窓幅（表示日数） | 1点の粒度 | 点の値 | スクラブ表示 |
|---|---|---|---|
| 〜45日 | 日 | 実測値 | 単日値＋日付 |
| 46〜240日 | 週(暦週・月曜始まり) | **週内実測の平均** | 「平均 xx.x／M/D–M/D」 |
| 241日〜 | 月(暦月) | **月内実測の平均** | 「平均 xx.x／YYYY年M月」 |

- 窓幅はピンチで7日〜全期間まで連続可変。ビンは常に**暦に固定**（どこへパンしても平均が安定）
- 粒度切替の瞬間は0.2sクロスフェード＋ハプティクスで通知
- ヘッダ統計:「傾向」=窓内の最初のビン値→最後のビン値の差。実表示範囲ラベル併記
- 点の位置=ビン中央（週なら木曜、月なら15日）

## C. 期間ナビゲーション

**【2026-07-28 更新】連続パンのため窓のアライメントは自由。**

| # | 決定項目 | 決定 |
|---|---|---|
| C1 | 窓のアライメント | 自由（連続パン）。**セグメントタップ時のみ暦にスナップ**（月=暦月等） |
| C2 | 窓の移動 | **1本指横ドラッグ（慣性つき）**＋‹›ボタン併設。未来側は今日まで |
| C3 | 初期表示 | 窓幅=直近30日（今日を右端に） |
| C4 | セグメントの役割 | 週/月/6M/年/全 は**窓幅ショートカット**（タップでその幅へアニメ変形） |

## D. ジェスチャ定義

**【2026-07-28 更新】ピンチ・スワイプをv1に採用（ユーザー決定）。**

| # | ジェスチャ | 動作 |
|---|---|---|
| D1 | **2本指ピンチ** | ズーム（窓幅を連続可変・ピンチ中心の日付を固定点に） |
| D2 | **1本指横ドラッグ** | パン（窓スライド・慣性つき） |
| D3 | **長押し(250ms)→ドラッグ** | スクラブ（垂直ライン＋値ポップオーバー。ビンに応じ単日値/平均+期間） |
| D4 | ハプティクス | スクラブで点を跨ぐ・粒度が切替わる瞬間に`hapticTap` |
| D5 | スクロール競合 | チャート領域に`touch-action:none`。縦スクロールはチャート外で |
| D6 | 実装 | 自作SVG＋素のPointerEvents。ジェスチャ中は軽量変形（translate/scale）、指を離したらビン再計算＋本描画。Y軸はrAFで連続リスケール |

## E. 軸・スケール — 「グラフの角度」

| # | 決定項目 | 推奨 |
|---|---|---|
| E1 | Y軸スケール | **窓内ビン値のmin/maxに上下8%パディング**で自動リスケール（Apple方式）。ゼロ基準にしない |
| E2 | 「角度」の暴れ対策 | 体重は**最小レンジ2kg**・ウエスト2cm・体脂肪2%を確保（変動が小さい週に線が激しく見える問題を防ぐ）|
| E3 | Y軸位置・目盛 | **右側**。目盛りは1/2/5×10ⁿの「きれいな刻み」で3〜5本 |
| E4 | X軸ラベル | 週=曜日、月=各週頭の日付、6M=月名、年=月頭文字 |
| E5 | 目標線・計画線 | 計画線（目標体重への直線）を薄く重ねる。トグルでON/OFF、デフォルトON |
| E6 | ズーム切替アニメ | 0.25sのクロスフェード＋Yスケール補間（framer-motion） |

## F. 描画技術

- **自作SVG継続**（最大点数〜400。ライブラリ追加なし）。ジェスチャは素のPointerEvents
- 新コンポーネント `components/InteractiveChart.tsx`（系列非依存: `{date,value}[]`＋単位＋最小レンジを受ける）
- 系列は**単系列切替**（体重 / ウエスト / 体脂肪 / 摂取kcal をチップで切替。重ね描きしない=C案的にクリーン）
- カロリー収支の累積は別カードとして維持（性質が違うため統合しない）

## G. チャート以外に必要なこと（C案展開）

1. **デザイントークン定義**: ink `#0e1116` / paper `#fbfbfa` / 罫線 `#e9eae7` / emerald `#059669`（データ色のみ例外的に許可）、文字階層6段、角丸4px、黒ボタン → globals.css全面改訂
2. **展開順**: トークン → AppShell（タブ/ヘッダ）→ 入力 → ダッシュボード（新チャート込み）→ 目標 → 設定 → シート/カレンダー → 食品
3. **絵文字→SVGアイコン総置換**（フィード・カード見出し・チップ・ボタン）
4. **判定ピル等の色ルール**: 「データの意味を持つ色（判定5色・PFC3色）だけ許可、装飾色は禁止」を提案
5. **ネイティブ配色**（ステータスバー・スプラッシュを #fbfbfa 系へ）→ 次回Codemagicビルドにまとめる
6. リングヒーローはC案の「水平ライン＋巨大数字」に置換
7. ダークモード: C案は**ライト固定**を提案（モノトーン設計はダーク反転で破綻しやすい）

## ユーザー確認が必要な5点

1. ズーム段「週/月/6M/年/全」の5段でよいか（Appleは6段=クォーター・学期あり）
2. v1はピンチ・スワイプパンなし（セグメント＋‹›）でよいか
3. チャート系列は単系列切替（体重/ウエスト/体脂肪/摂取）でよいか
4. 判定ピルの5色は「データ色」として残してよいか（完全モノトーン化も可）
5. ダークモード廃止（ライト固定）でよいか
