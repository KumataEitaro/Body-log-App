# 法的防御の設計台帳 — 2026-09-01（feat/legal-hardening）

「食事の制約（除外アラート）」の実装で、健康被害を主張されうる面が増えた。
米国からのダウンロードは避けられないため、**日本法準拠だけでは薄い**。
ここに防御の層と、なぜそれを入れたかを残す。**単独で削る・弱める変更をしないこと。**

## 前提となる脅威モデル

1. アレルギー症状が出て「アプリが警告しなかった」と主張される（製造物責任・不実表示）
2. 極端な減量の結果に対して健康被害を主張される（既存の安全ガードで一次防御済み）
3. 上記が**クラスアクション**として提起される（米国では個別請求より桁違いに重い）
4. 「規約に同意していない」と同意の成立自体を争われる（提示がないと実際に負ける）

## 実装した防御（層ごと）

### L1. 機能の設計そのもの（最も強い防御）
- 肯定的断定を出さない（「安全」「食べられる」「〜フリー」「緑チェック」を作らない）
- 警告は high / maybe の二値のみ。無警告は保証でないと**常設表示**
- サーバー側でも `none` を落とし、AIに「含まれていません」と書かせない
- 詳細: docs/DIET-MODES.md §6

### L2. 同意の成立（clickwrap相当）
- **新規登録画面に規約・プライバシーへのリンクを明示**（2026-09-01追加。
  これが無い状態では「アカウント作成で同意」条項が争われて負ける可能性が高かった）
- 医療免責・16歳未満不可も登録画面に明記
- 食事の制約は**機能ONの前に専用の同意ゲート**＋同意日時をDBに記録（profiles.diet_consent_at）

### L3. 利用規約（app/terms/page.tsx）
| 条 | 防御内容 | 理由 |
|---|---|---|
| 2条 | AS IS・特定結果を約束しない | 効果保証の主張を封じる |
| 3条 | 16歳未満不可・妊娠授乳・摂食障害の制限 | 脆弱な利用者への線引き |
| 4条 | 医療免責・専門家の代替でない・緊急時は受診 | 医療機器規制と過失主張への防御 |
| 4条の2 | 食事の制約の非保証6項目 | B-18専用。混入・仕様変更・見落としを明記 |
| 5条 | 出力を安全確認に使う行為を**禁止事項**に | 「用法外使用」と言える構成にする |
| 6条 | 第三者AI/DBの非保証 | Gemini・Open Food Factsの誤りを引き受けない |
| 8条 | 保証の完全排除＋間接損害排除＋**責任上限（12か月の支払額または1,000円の低い方）** | 米国型の Limitation of Liability。金額を明示しないと無効になりやすい |
| 9条 | 不利益変更は**30日前告知** | 一方的改定の不当性を回避（2026年の実務標準） |
| 10条 | 日本法・東京地裁専属＋**国外居住者は日本での仲裁**＋**クラスアクション放棄**＋**1年の請求期間制限** | 集合的手続を個別化する。FAA下で仲裁合意は広く執行される |
| 11条 | 輸出管理・制裁 | 制裁対象地域からの利用を排除 |
| 12条 | 米国政府ユーザー（FAR/DFARS） | 政府調達時の権利限定の定型 |
| 13条 | 可分性・完全合意 | 一部無効時に全体が倒れない |

### L4. 運用・証跡
- 同意日時の記録（食事の制約）
- 規約に最終更新日を表示
- クラッシュレポート（crash_reports）で不具合の事実関係を再現できる

## 未対応（残タスク）

1. **ストア説明文への明記**（App Store / Google Play の説明欄に
   「推定であり安全確認用ではない」を入れる）… 提出物なので熊田さん作業
2. **プライバシーポリシーの英語版**（現在は日本語のみ。米国・EU向けには
   英語版と、CCPA/GDPRの権利行使窓口の記載が望ましい）
3. **米国弁護士のレビュー**（特に仲裁条項とクラスアクション放棄の文言。
   州によって執行力が変わる。本格的に米国展開するなら投資に見合う）
4. **保険**（個人開発でも E&O / 生産物賠償責任保険は検討価値あり。
   売上が立ってからでよいが、米国展開の前には見積りを取る）
5. **地域制限という選択肢**: 最も確実な防御は「食事の制約機能を日本国内のみで提供」
   （StoreKit/Play の地域別配信、またはアプリ内で端末地域を見て機能を出さない）。
   売上とリスクを見て判断する。現状は全地域で提供

## 参考にした実務
- 仲裁合意・クラスアクション放棄は主要アプリ（Microsoft等）の標準構成。
  クリックラップでの同意取得が執行力の前提（TermsFeed / Davis+Gilbertの判例解説）
- 責任上限は「支払額 or 少額の固定額」の二択方式が一般的
- 30日前の事前告知は2026年のモバイルアプリ規約のベストプラクティス
